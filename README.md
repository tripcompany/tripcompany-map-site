# 트립컴퍼니 가이드 지도 — 프로토타입

세계지도 → 국가 클릭 시 확대 → 도시 마커 → 오른쪽 패널에 유튜브 영상 목록이 뜨는
인터랙티브 지도 프로토타입입니다.

`app.js`의 `CONFIG.dataSource` 값이 `"csv"`로 되어 있어서, 지금 바로 열면 아직
CONFIG.csv 링크가 실제 주소로 바뀌지 않았기 때문에 "데이터를 불러오지 못했습니다"
안내만 보일 수 있습니다. 샘플 데이터(일본/베트남/태국)로 먼저 화면 동작을 확인해보고
싶으시면 `CONFIG.dataSource` 값을 `"sample"`로 잠깐 바꿔서 열어보시면 됩니다.

폴더 구성은 다음과 같습니다. `index.html`이 메인 페이지, `style.css`가 디자인,
`app.js`가 지도·상태 전환·영상 패널을 담당하는 핵심 로직, `data/sample-data.js`가
테스트용 샘플 데이터입니다.

## 1. 내 컴퓨터에서 바로 미리보기

`index.html` 파일을 더블클릭해서 브라우저로 열면 바로 확인할 수 있습니다.
짙은 초록색으로 표시된 일본·베트남·태국을 클릭해보시고, 도시 마커(주황색 점)도
클릭해서 영상 목록이 바뀌는지 확인해보세요.

## 2. 완전 무료로 인터넷에 올리기 (Netlify)

가장 빠른 방법은 Netlify Drop입니다. 브라우저에서 app.netlify.com/drop 페이지를 열고,
이 프로젝트 폴더 전체(`tripcompany-map-site` 폴더)를 그 화면에 마우스로 끌어다 놓기만
하면 됩니다. 몇 초 안에 `무작위이름.netlify.app` 형태의 무료 주소가 생기고, 그 주소로
바로 접속해서 실제 서비스처럼 테스트할 수 있습니다. 나중에 갖고 계신 도메인을 연결하는
것도 Netlify 사이트 설정의 "Domain settings"에서 무료로 가능합니다.

Vercel을 선호하시면 vercel.com에 가입한 뒤 이 폴더를 그대로 업로드하거나, GitHub
저장소에 올려두고 Vercel에서 그 저장소를 "Import"하는 방식으로 배포할 수 있습니다.
이 프로젝트는 별도 빌드 과정이 없는 순수 정적 파일이라 두 서비스 모두 설정 없이 바로
배포됩니다.

## 3. 샘플 데이터를 실제 구글시트로 바꾸기 (웹 게시 + CSV 방식, 완전 무료)

`app.js` 맨 위 `CONFIG.dataSource` 값은 이제 기본으로 `"csv"`로 되어 있습니다.
구글시트를 "웹에 게시"해서 나온 CSV 링크를 직접 불러오는 방식이라, SheetDB 같은
중계 서비스 없이도 요청 횟수 제한 없이 완전히 무료로 쓸 수 있습니다.

먼저 구글시트에 Countries / Cities / Videos 탭 세 개를 만들고 데이터를 채웁니다
(열 구성은 아래 4번 항목 참고). 그다음 구글시트 메뉴에서 **파일 > 공유 > 웹에 게시** 를
누릅니다. 게시 대화상자에서 첫 번째 드롭다운을 "전체 문서"가 아니라 **"Countries"
탭 하나만** 선택하고, 두 번째 드롭다운을 "쉼표로 구분된 값(.csv)"으로 바꾼 뒤
"게시" 버튼을 누릅니다. 확인 창이 뜨면 게시를 확정하고, 생성된 링크 주소를
복사해 둡니다.

이 과정을 Cities 탭, Videos 탭에 대해서도 각각 한 번씩 더 반복합니다(드롭다운에서
탭만 바꿔서 다시 게시하면 됩니다). 총 세 개의 링크가 생기고, 각 링크는
`.../pub?gid=숫자&single=true&output=csv` 형태입니다.

이렇게 얻은 세 링크를 `app.js`의 `CONFIG.csv.countries`, `CONFIG.csv.cities`,
`CONFIG.csv.videos`에 각각 그대로 붙여넣으면 끝입니다. 이후로는 사이트를 새로
배포하지 않아도 구글시트를 수정하면 몇 분 내로 지도와 영상 목록에 반영됩니다
(구글이 게시된 CSV를 잠깐 캐시하기 때문에 수정 직후 바로는 안 보일 수 있습니다).

시트를 아예 통째로 비공개로 유지하고 싶지 않다면(웹 게시는 그 데이터를 링크를 아는
사람 누구나 볼 수 있게 만듭니다) SheetDB 방식을 계속 쓰셔도 됩니다 — `CONFIG.dataSource`를
`"sheetdb"`로 바꾸고 `CONFIG.sheetdb.baseUrl`에 SheetDB 주소를 넣으면 되는데, 이 경우
무료 플랜은 월 500회 요청까지만 무료라는 점을 감안하셔야 합니다.

## 4. 국가 코드(country_code)는 왜 숫자인가요

지도의 국경 데이터가 나라를 ISO 3166-1 "숫자" 코드로 구분하기 때문에, 구글시트의
Countries/Cities/Videos 탭에 적는 country_code도 반드시 이 숫자 코드와 똑같이
맞춰야 지도와 데이터가 연결됩니다. 자주 쓰일 만한 여행지 코드를 아래에 정리해
두었으니 참고하시고, 목록에 없는 나라는 "ISO 3166-1 numeric"으로 검색하면 바로
찾을 수 있습니다.

| 중국 | 156 | 대만 | 158 |
| 홍콩 | 344 | 베트남 | 704 |
| 태국 | 764 | 필리핀 | 608 |
| 싱가포르 | 702 | 말레이시아 | 458 |

| 라오스 | 418 | 미얀마 | 104 |

새 나라를 추가할 때는 Countries 탭에 이 숫자 코드와 국가명, has_video를 TRUE로
넣고, Cities 탭에 그 나라의 도시(위도·경도 포함)를, Videos 탭에 관련 영상을
추가하면 됩니다. 지도 그림 작업은 전혀 필요 없습니다.

싱가포르처럼 나라 자체가 도시나 다름없어서 Cities 탭에 따로 도시를 추가하기
애매한 경우에는, Cities 탭에 아무것도 넣지 않아도 됩니다. 다만 이런 아주
작은 나라는 지도 표시 위치를 직접 지정해줘야 할 수 있는데, 자세한 방법은
바로 아래 5번 항목을 참고하세요.

## 5. 아주 작은 나라 표시하기 (지금은 싱가포르는 해당 없음)

지도의 국경 데이터는 용량을 줄이기 위해 단순화된 버전을 쓰고 있습니다.
지금 쓰는 50m 해상도 데이터에는 싱가포르 정도 크기의 나라는 도형이 들어있어서
정상적으로 색칠되고 표시되지만, 모나코·바티칸처럼 그보다 훨씬 더 작은 나라는
이 데이터에도 도형 자체가 없을 수 있습니다. 그런 나라는 국경 도형 위치를
계산할 수 없어서, 지도에 점을 찍을 위치를 사람이 직접 알려줘야 합니다.

방법은 간단합니다. Countries 탭에 `map_center_lat`, `map_center_lng`라는
열을 두 개 추가하고, 그 나라 행에 위도·경도를 적어주면 됩니다. 이 두 열은
선택 사항이라 값을 안 채운 다른 나라에는 전혀 영향을 주지 않습니다. Cities
탭에는 여전히 아무것도 안 넣어도 되고, Videos 탭에 country_code만 채우고
city_id는 비워서 국가 단위 영상을 등록해두면, 지정한 좌표 위치에 점이 하나
표시되고 클릭하면 그 나라의 영상 목록이 뜹니다. 이런 나라는 국경 모양
자체가 지도에 안 그려지기 때문에(색칠된 영역은 안 보입니다) 점만으로
표시된다는 점은 참고해 주세요.

나중에 이 나라를 지역별로 더 세분화하고 싶어지면, 그때 Cities 탭에 도시를
추가하면 됩니다 — 도시가 하나라도 생기는 순간 이 나라 중심점 대신 보통
나라들처럼 도시별 점이 표시됩니다.

일본, 베트남처럼 어느 정도 크기가 있는 나라인데 아직 Cities 탭에 도시를
안 넣은 경우에는 map_center 없이도 나라 도형의 중심에 자동으로 점이
표시되니, map_center_lat/lng는 정말 작은 나라에서 지도에 아무 점도 안 보일
때만 채워주면 됩니다.

## 6. 여러 도시를 비교하는 영상 등록하기

"도쿄·오사카·후쿠오카·삿포로 물가 비교"처럼 한 영상이 여러 도시를 함께
다루는 경우, 그 영상을 도시 수만큼 여러 번 복사해서 넣을 필요가 없습니다.
Videos 탭의 city_id 칸에 관련된 도시들의 city_id를 쉼표(,)로 이어서 한
번에 적으면 됩니다.

예: `JP-TOKYO,JP-OSAKA,JP-FUKUOKA,JP-SAPPORO`

이렇게 등록한 영상 한 줄은 도쿄·오사카·후쿠오카·삿포로 중 어느 도시를
선택해도 그 목록에 함께 나타납니다. 영상 카드에는 "도쿄 · 오사카 · 후쿠오카
· 삿포로 비교"처럼 어떤 도시들을 비교하는 영상인지 작게 표시되어서, 왜 여러
도시 화면에 같은 영상이 보이는지 헷갈리지 않습니다. 지도 위 도시 점 색깔에도
이 영상의 채널이 반영됩니다.

다만 일본을 선택하고 아직 도시를 고르지 않은 "일본 전체" 화면에는 뜨지
않습니다 — 비교 영상은 관련된 도시를 직접 선택했을 때만 보이고, 나라
전체를 클릭했을 때는 나오지 않도록 되어 있습니다.

참고로 city_id를 완전히 비워두면 지금까지처럼 "국가 전체 개요" 영상(나라를
선택하면 바로 보임)이고, city_id에 도시 하나만 적으면 지금까지처럼 그 도시
전용 영상입니다. 쉼표로 2개 이상 적으면 "여러 도시 비교" 영상으로 인식되어
해당 도시들을 선택했을 때만 노출되고, 나라 전체 화면에는 노출되지 않습니다.

## 7. 여러 나라를 비교하는 영상 등록하기

"일본 vs 베트남 여행 물가 비교"처럼 나라 단위로 비교하는 영상은, 위의 도시
비교와 똑같은 방식으로 country_code 칸에 나라들의 country_code를 쉼표(,)로
이어 적으면 됩니다. 이때 city_id는 비워두세요(특정 도시가 아니라 나라
전체를 비교하는 영상이기 때문입니다).

예: `392,704` (일본, 베트남)

이렇게 등록하면 일본을 선택했을 때의 "일본 전체" 화면과, 베트남을
선택했을 때의 "베트남 전체" 화면 양쪽에 이 영상이 자동으로 나타납니다.
영상 카드에는 "일본 · 베트남 비교"처럼 표시됩니다. 비교 대상인 나라들은
모두 Countries 탭에서 has_video가 TRUE로 되어 있어야 지도에서 선택할 수
있다는 점은 기존과 동일합니다.

참고로 도시와 나라 비교를 동시에 쓸 수도 있습니다 — 예를 들어 city_id에
`JP-TOKYO,VN-HANOI`(도쿄, 하노이)처럼 서로 다른 나라의 도시를 함께 적으면
두 도시를 각각 선택했을 때 모두 노출됩니다. 다만 위에서 설명한 것처럼
city_id가 채워진(도시 2곳 이상) 영상은 나라 전체 화면에는 뜨지 않으므로,
country_code에 `392,704`를 함께 적어도 "일본 전체"/"베트남 전체" 화면에는
노출되지 않고 도쿄·하노이 도시 화면에만 노출됩니다.

## 8. 두 채널(트립콤파니 / 여행하는트콤) 표시하기

Videos 탭에 `channel`이라는 열을 하나 추가하고, 그 브이로그 채널의 영상이면
`여행하는트콤`이라고 적어주세요. 비워두거나 다른 값을 적으면 지금까지처럼
트립콤파니 영상으로 처리되기 때문에, 기존에 이미 입력해둔 영상들은 전혀
손댈 필요가 없습니다.

지도에서는 트립콤파니 영상이 있는 도시는 주황색 점으로, 여행하는트콤 영상이
있는 도시는 그보다 조금 작은 파란색 점으로 표시됩니다. 한 도시에 두 채널의
영상이 모두 있으면 두 점이 살짝 겹쳐서 함께 보입니다. 지도 왼쪽 아래에
어떤 색이 어떤 채널인지 보여주는 작은 범례도 넣어뒀습니다. 오른쪽 영상
목록에서도 각 영상 제목 아래에 채널 이름표가 붙어서 어느 채널 영상인지
바로 구분할 수 있습니다.

## 9. 광고 자리

헤더 아래(728×90)에 점선으로 표시된 빈 자리가 큰 광고 슬롯입니다.
`index.html`에서 `id="ad-slot-top"`로 표시된 부분을 찾아서, 나중에 구글
애드센스 등의 광고 코드를 그 안에 그대로 넣으면 됩니다. 지금은 이 자리를
클룩(14번 항목) → 아고다 순서로 채우고 있습니다.

오른쪽 영상 목록 쪽 광고는 영상 카드와 같은 높이(70px)로 작게 만들어서
목록 맨 마지막 영상 바로 아래에 자동으로 붙도록 `app.js`의
`buildInlineAdHtml()` 함수에서 만들고 있습니다. 이 광고 자리에 실제 코드를
넣으려면 `app.js`에서 이 함수 부분을 찾아 반환하는 HTML을 바꾸면 됩니다.
지금은 트립닷컴(17번 항목) → 아고다 순서로 채우고 있습니다.

**제휴 배너 문구 규칙**: 아고다·클룩·트립닷컴 배너 모두 "제휴 링크 ·
예약하시면 트콤 가이드 제작에 도움이 돼요"라는 같은 문구로 고지하고
있습니다. 앞으로 새 제휴 배너(이미지든 텍스트든)를 추가할 때도 이 문구를
그대로 써주세요 — 수익을 "사이트 운영"이 아니라 "트콤 가이드 제작"을
돕는 것으로 표현하는 쪽을 선호하십니다.

## 10. 접속자 위치에 맞춰 초기 지도 위치 설정

`app.js`의 `CONFIG.geoLocate.enabled`가 `true`로 되어 있으면, 접속자의 IP로
대략적인 위치를 확인해서 처음 지도가 뜰 때 그 근처가 보이도록 자동으로
맞춥니다(국가를 강조 표시하거나 선택하는 건 아니고, 단순히 지도의 시작
위치·줌만 옮깁니다). 무료이고 키가 필요 없는 geojs.io 서비스를 쓰고 있고,
실패하더라도(방문자의 네트워크가 막혀 있는 경우 등) 조용히 기본 위치로
남기 때문에 사이트가 깨지지는 않습니다. 이 기능을 끄고 싶으면
`CONFIG.geoLocate.enabled`를 `false`로 바꾸면 됩니다.

지도 왼쪽 위의 "내 위치" 버튼도 같은 값을 재사용합니다. 나라를 선택해서
확대한 상태든 아니든 언제 눌러도 선택을 풀고, 이 IP 기반 위치가 넓게 보이는
화면(사이트에 처음 접속했을 때와 같은 화면)으로 돌아갑니다. 브라우저의
정확한 GPS 권한을 요청해서 바짝 확대하는 방식이 아니라서 권한 팝업이 뜨지
않고, 페이지 로딩 시 이미 확인해둔 값을 그대로 쓰기 때문에 다시 눌러도
네트워크 요청 없이 바로 이동합니다.

## 11. 알려진 제약 사항

지도 국경 데이터와 유튜브 영상, 그리고 실제 서비스 전환 시의 구글시트 데이터는
모두 인터넷에서 불러오는 방식이라 오프라인 환경에서는 지도가 뜨지 않습니다.
웹 게시 + CSV 방식은 요청 횟수 제한은 없지만, 게시된 데이터가 링크를 아는
누구에게나 공개된다는 점과 수정 후 반영까지 몇 분 정도 캐시 지연이 있을 수
있다는 점은 참고해 주세요. 샘플 데이터의 유튜브 영상은 전부 테스트용
placeholder이니 실제 트립컴퍼니 영상으로 교체해서 쓰세요.

## 12. 트콤 실시간 위치 표시하기

여행하는트콤이 지금 실제로 있는 위치를 지도 위에 동그란 얼굴 사진 마커로
보여주는 기능입니다(파란 테두리 + 은은한 파동 + 빨간 "현재 위치" 배지).
나라를 클릭해서 확대해도 사라지지 않고 항상 지도 위에 떠 있습니다.

(배지 문구는 원래 "LIVE"였는데, 실시간 스트리밍 중이라고 오해할 수
있어서 "현재 위치"로 바꿨습니다.)

**설정 방법 (한 번만 하면 됩니다)**

1. Countries/Cities/Videos와 같은 구글시트에 **"Status"** 라는 새 탭을 만듭니다.
2. 첫 번째 줄(헤더)에 `lat`, `lng`, `location_name`, `updated_at` 네 칸을
   순서대로 적습니다.
3. 그 아래 두 번째 줄 딱 한 줄에 지금 있는 위치를 적습니다. 예를 들어
   `36.9856` / `-110.0977` / `모뉴먼트 밸리, 미국` / `2026-09-10` 처럼요.
   (항상 이 두 번째 줄 값만 지도에 표시되므로, 세 번째 줄부터는 안 만들어도
   됩니다.)
4. **파일 > 공유 > 웹에 게시** 에서 이번엔 "Status" 탭을 골라 "쉼표로 구분된
   값(.csv)"으로 게시하고, 생성된 링크를 복사합니다.
5. `app.js`의 `CONFIG.csv.status`에 그 링크를 붙여넣습니다.

**위치가 바뀔 때마다 갱신하는 방법**

새로 배포할 필요 없이, 구글시트의 Status 탭 두 번째 줄 셀(위도/경도/지명/날짜)만
고치면 됩니다. 노트북이 없어도 폰의 구글시트 앱으로 바로 고칠 수 있어요. 지금
내 위도/경도를 가장 빠르게 확인하는 방법은 폰에서 구글 지도 앱을 열고 **파란
점(내 위치)을 길게 눌러서** 나오는 좌표를 복사하는 겁니다. 시트를 수정하면
게시된 CSV에는 보통 몇 분 안에 반영되고, 이미 사이트를 열어둔 사람 화면에도
새로고침 없이 최대 5분 안에 자동으로 반영됩니다(이 간격은 `app.js`의
`CONFIG.trekomStatus.refreshIntervalMinutes` 값을 바꾸면 조절할 수 있습니다).

**마커 얼굴 사진 바꾸기**

`images/trekom-live-avatar.jpg` 파일을 원하는 사진으로 교체하면 됩니다. 정사각형에
가까운 사진일수록(동그랗게 잘리는 건 CSS가 자동으로 처리합니다) 자연스럽습니다.

**한 번 탭으로 GPS 좌표 자동 입력하기 (선택)**

구글시트 자체는 폰의 GPS에 접근할 수 없어서, 시트를 여는 것만으로 좌표가 저절로
채워지지는 않습니다. 그래서 GPS를 자동으로 읽어주는 작은 "위치 업데이트 전용
페이지"를 만드는 방법 두 가지를 준비했습니다 — **A) Apps Script 방식** 이 더
간단하지만, 계정에 따라 배포 중 "This app is blocked / 이 앱이 차단되었습니다"
오류가 뜰 수 있습니다(주로 구글 계정에 "고급 보호 프로그램"이 켜져 있을 때). 그런
경우엔 **B) 구글 폼 방식** 을 대신 쓰면 됩니다 — 구글의 자체 서비스(폼 + 시트
연동)만 쓰기 때문에 이 차단 자체가 발생하지 않습니다.

### A. Apps Script 방식 (`google-apps-script/` 폴더)

열면 자동으로 GPS 위치를 읽고, 버튼 한 번 누르면 그 좌표가 Status 탭에 바로
기록되는 페이지입니다. 구글의 무료 스크립트 기능(Apps Script)으로 만든 거라 별도
서버나 비용이 들지 않습니다.

설치 방법 (한 번만 하면 됩니다):

1. 이 Status 탭이 있는 구글시트를 열고, 메뉴에서 **확장 프로그램 > Apps Script** 를
   누릅니다.
2. 새 창(스크립트 편집기)이 열리면 기본으로 있는 `Code.gs` 내용을 전부 지우고,
   이 zip 안의 `google-apps-script/Code.gs` 내용을 그대로 복사해서 붙여넣습니다.
3. 왼쪽 파일 목록 옆 **"+" 버튼 > HTML** 을 눌러 파일을 하나 추가하고, 이름을
   정확히 **`Page`** 로 짓습니다(확장자 `.html`은 자동으로 붙습니다). 그 안에
   `google-apps-script/Page.html` 내용을 그대로 복사해서 붙여넣습니다.
4. 오른쪽 위 **배포 > 새 배포** 를 누르고, 유형에서 톱니바퀴를 눌러 **"웹 앱"** 을
   선택합니다. "실행 계정"은 **나**, "액세스 권한이 있는 사용자"는
   **"Google 계정이 있는 모든 사용자"** 로 두고 배포합니다(폰이 이미 본인 구글
   계정으로 로그인돼 있으면 별도 로그인 없이 바로 열립니다. 누구나 들어올 수
   있게 하고 싶다면 "모든 사용자"로 바꿔도 되지만, 그러면 이 링크를 아는 사람은
   누구든 위치를 바꿀 수 있으니 링크를 아무 데나 공유하지 마세요).
5. 처음 배포할 때 구글이 권한 확인 화면을 보여줍니다("확인되지 않은 앱" 경고가
   떠도 본인이 만든 스크립트이니 "고급 > (프로젝트 이름)로 이동" 눌러서 진행하면
   됩니다). 완료되면 `https://script.google.com/macros/s/.../exec` 형태의
   웹 앱 주소가 나옵니다. 이 주소를 폰 홈 화면에 바로가기로 추가해두세요.

**사용 방법**: 새 위치에 도착했을 때 그 바로가기를 탭 → 위치 권한을 허용하면
좌표가 자동으로 채워짐 → 지명을 적고(생략 가능) "지금 위치로 업데이트" 버튼
탭 → 끝입니다. Status 탭의 lat/lng/updated_at이 자동으로 갱신되고, 지도에는
평소처럼 몇 분 안에 반영됩니다.

나중에 `Code.gs`나 `Page.html`을 고치고 싶으면 스크립트 편집기에서 코드를 수정한
뒤 **배포 > 배포 관리 > 수정(연필 아이콘) > 새 버전** 으로 다시 배포해야 바뀐
내용이 실제 웹 앱 주소에 반영됩니다.

### B. 구글 폼 방식 (Apps Script가 차단될 때, `update-location-a057f5cc8c98.html`)

Apps Script는 배포할 때 구글의 OAuth 권한 승인 화면을 거치는데, 이 과정에서
"This app is blocked / 이 앱이 차단되었습니다"라는 메시지가 뜨고 더 진행할
방법이 없는 경우가 있습니다. 주로 그 구글 계정에 **고급 보호 프로그램(Advanced
Protection Program)**이 켜져 있을 때 생기는 현상이라, 계정 보안 설정을 건드리고
싶지 않다면 이 방식을 대신 쓰면 됩니다. Apps Script(별도 권한 승인이 필요한 개인
스크립트) 대신, 구글 폼 + 스프레드시트 연동이라는 구글 자체 기능만 쓰기 때문에
이런 차단이 아예 발생하지 않습니다. 대신 마지막에 "제출" 버튼을 한 번 더 눌러야
하는 차이가 있습니다.

**작동 방식**: 매번 같은 줄을 덮어쓰는 대신, 제출할 때마다 새 줄이 맨 아래에
쌓이는 방식입니다(위치 이동 기록이 자연스럽게 남는 셈입니다). 지도는 항상 가장
마지막 줄의 값을 읽어서 보여주므로 신경 쓸 게 없습니다.

**설정 방법 (한 번만 하면 됩니다)**

1. [forms.google.com](https://forms.google.com)에서 새 양식을 만듭니다(제목은
   자유롭게, 예: "트콤 위치 업데이트").
2. **단답형** 질문을 3개 추가하고, 질문 제목을 아래처럼 정확히(대소문자와
   철자 그대로) 적습니다 — 이 제목이 나중에 시트의 헤더 칸 이름이 됩니다.
   - `lat`
   - `lng`
   - `location_name` (필수 응답 끄기를 켜서 생략 가능하게 해도 됩니다)
3. 오른쪽 위 **응답** 탭 → 초록색 스프레드시트 아이콘 → **기존 스프레드시트
   선택**으로 Countries/Cities/Videos가 있는 그 구글시트를 골라 연결합니다.
   "설문지 응답 1" 같은 이름의 새 탭이 자동으로 생깁니다.
4. 그 새 탭을 **파일 > 공유 > 웹에 게시** 에서 "쉼표로 구분된 값(.csv)"으로
   게시하고, 생성된 링크를 `app.js`의 `CONFIG.csv.status`에 붙여넣습니다
   (기존에 Status 탭 링크를 넣어뒀다면 그 자리를 이 링크로 바꾸면 됩니다).
5. 폼 편집 화면 오른쪽 위 **⋮(점 3개) 메뉴 > 미리 채워진 링크 받기** 를
   누릅니다. lat/lng/location_name 칸에 아무 값이나(예: `1`, `2`, `테스트`)
   입력하고 **링크 받기 > 링크 복사** 를 누릅니다.
6. 복사된 링크는 이런 모양입니다:
   `https://docs.google.com/forms/d/e/긴문자열/viewform?usp=pp_url&entry.111=1&entry.222=2&entry.333=테스트`
   여기서 `?` 앞부분(`.../viewform`까지)과, `1`·`2`·`테스트`를 각각 입력했던
   `entry.숫자` 세 개를 확인합니다(순서는 폼에 배치한 순서와 같습니다).
7. 이 프로젝트 폴더의 `update-location-a057f5cc8c98.html` 파일을 열어서 맨 아래
   `<script>` 안 `FORM_CONFIG` 값 세 개를 6번에서 확인한 값으로 채웁니다:
   ```
   formActionBase: "https://docs.google.com/forms/d/e/긴문자열/viewform",
   latEntry: "entry.111",
   lngEntry: "entry.222",
   nameEntry: "entry.333"
   ```
8. 저장한 뒤, 평소처럼 프로젝트 폴더 전체를 Netlify Drop에 다시 올리면
   `update-location-a057f5cc8c98.html`도 함께 배포됩니다. 접속 주소는
   `내-사이트-주소/update-location-a057f5cc8c98.html` 형태입니다. 이 주소를 폰 홈
   화면에 바로가기로 추가해두세요.

**다른 사람이 이 링크로 접속 못 하게 하려면**

이 페이지는 정적 파일이라 서버 쪽에서 비밀번호를 확인하는 진짜 로그인 기능은
붙일 수 없습니다. 대신 실질적으로 도움이 되는 방법 두 가지를 이미 적용해뒀고,
하나는 직접 설정해주면 됩니다.

- **추측하기 어려운 파일명 (이미 적용됨)**: 파일명을 `update-location.html`
  같은 뻔한 이름 대신 `update-location-a057f5cc8c98.html`처럼 무작위 문자열이
  섞인 이름으로 만들어뒀습니다. `index.html`이나 사이트 어디에서도 이 페이지로
  가는 링크를 걸어두지 않았기 때문에, 이 주소를 직접 아는 사람(당신)만 접속할
  수 있고 사이트를 둘러보다가 우연히 발견될 일은 없습니다. 검색엔진에 노출되는
  것도 `<meta name="robots" content="noindex">` 태그로 막아뒀습니다. 다만 이건
  "아는 사람만 아는" 수준의 보호라, 주소를 캡처한 화면이나 메시지를 다른 사람과
  공유하지 않도록 주의해 주세요.
- **구글 폼에 로그인 요구하기 (선택, 직접 설정 필요 — 진짜 보안 경계)**: 폼
  편집 화면에서 **설정(⚙) > 응답** 탭으로 가서 **"로그인 필요"** 를 켜면, 구글
  계정으로 로그인하지 않은 사람은 아예 제출할 수 없게 됩니다. 이게 유일하게
  진짜 인증에 가까운 방법입니다. 단, 바로 아래 **"응답을 1회로 제한"** 옵션은
  켜지 마세요 — 그걸 켜면 같은 계정으로는 평생 딱 한 번만 제출할 수 있어서,
  위치를 옮길 때마다 다시 제출해야 하는 이 용도와는 맞지 않습니다.

이 두 가지를 합치면 "우연히 발견되거나 무심코 접속되는 것"은 사실상 막을 수
있지만, 주소와 로그인 정보까지 알아내려고 작정한 사람을 완벽히 막는 건 이
구조(서버 없는 정적 사이트) 자체의 한계이니 참고해 주세요.

**사용 방법**: 새 위치에 도착했을 때 그 바로가기를 탭 → 위치 권한을 허용하면
좌표가 자동으로 채워짐 → 지명을 적고(생략 가능) "다음(구글 폼으로 이동)" 버튼
탭 → 구글 폼 화면으로 넘어가면 값이 이미 채워져 있으니 **제출** 버튼을 한 번
더 탭 → 끝입니다. 지도에는 평소처럼 몇 분 안에 반영됩니다.

## 13. 수익화 준비 — 개인정보처리방침 & 쿠키 동의 배너

구글 애드센스를 신청하거나 운영하려면 (1) 개인정보처리방침 페이지와 (2) 쿠키
사용에 대한 이용자 동의 절차가 필요합니다. 이번에 두 가지를 미리 만들어
뒀습니다.

**추가된 파일**
- `privacy.html` — 개인정보처리방침 페이지. 푸터의 "개인정보처리방침" 링크로
  들어갈 수 있습니다.
- `cookie-consent.js` — 화면 하단 쿠키 동의 배너. 처음 방문한 사람에게만
  "동의 / 거부" 배너가 뜨고, 한 번 선택하면 브라우저에 저장돼서 다시 묻지
  않습니다.

**개인정보처리방침 페이지 안내**

`privacy.html`의 운영자명·문의 이메일(`cms9304@gmail.com`, "트립콤파니")은
확인을 마친 최종 값으로 그대로 게시하면 됩니다. 나중에 문의 이메일이나
운영자명이 바뀌면 `privacy.html`에서 제9조 표의 해당 값만 직접 고쳐주시면
됩니다. 이 문서는 **법률 자문이 아닌 템플릿** 이라, 애드센스가 승인되고
광고·트래픽 규모가 커지면 변호사나 법무사의 검토를 한 번 받아보시길
권장드립니다.

**쿠키 동의 배너는 이렇게 동작합니다**

방문자가 처음 사이트에 들어오면 화면 아래에 "이 사이트는 서비스 개선과 광고
제공을 위해 쿠키를 사용할 수 있어요…" 배너가 뜨고, "동의"나 "거부" 버튼을
누르면 그 선택이 브라우저에 저장되어 다음 방문부터는 배너가 다시 뜨지
않습니다. 지도나 유튜브 영상 이용 자체는 동의 여부와 상관없이 그대로 됩니다.

나중에 실제 애드센스 광고 코드를 `ad-slot-top` 등에 넣으실 때, 동의 여부를
확인하고 싶으면 아무 스크립트에서나 이렇게 쓸 수 있습니다.

```javascript
if (window.TCConsent.isGranted()) {
  // 동의한 사람에게만 보여줄 코드
}
```

**구글 애드센스 승인/운영 시 참고사항 (중요)**

지금 만든 배너는 "쿠키를 쓴다는 걸 알리고 선택을 저장"하는 기본적인
동의 배너입니다. 그런데 애드센스로 **유럽(EEA)·영국·스위스** 방문자에게
광고를 보여주는 경우, 구글은 자체 정책상 구글이 인증한 CMP(동의관리
플랫폼)를 쓰도록 요구합니다. 가장 쉬운 방법은 애드센스 계정에 로그인한
뒤 좌측 메뉴의 **"개인정보 보호 및 메시지"(Privacy & messaging, 예전 이름
Funding Choices)** 로 들어가서 동의 메시지를 만들면, 구글이 직접
`<script>` 코드 한 줄을 만들어줍니다. 이건 구글 계정 로그인이 필요한
단계라 제가 대신 만들어드릴 수 없어서, 애드센스 승인을 받으신 뒤에 그
화면에서 나온 코드를 `index.html`의 `<head>` 안에 붙여넣으시면 됩니다.
유럽 방문자가 거의 없는 개인 블로그/유튜브 채널 소개 사이트 단계에서는
지금 만든 배너만으로도 충분히 정상적으로 운영하실 수 있습니다.

## 14. 아고다(Agoda) 숙소 예약 제휴 배너

애드센스 심사를 받기 전까지, 헤더 아래 큰 광고 자리와 영상 목록 맨 아래
작은 광고 자리를 아고다 숙소 예약 제휴 배너로 대신 채울 수 있습니다.
방문자가 지금 보고 있는 나라·도시에 맞춰 "OOO 숙소 최저가로 예약하기"
문구가 자동으로 바뀌고, 그 링크로 예약이 이루어지면 수수료를 받습니다.

**1) 아고다 파트너 프로그램 가입하기**

1. [partners.agoda.com](https://partners.agoda.com/)에서 가입 신청을 합니다.
   웹사이트 주소(지금 만들고 계신 이 지도 사이트), 운영 형태 등을 입력하면
   되고, 심사에는 보통 며칠이 걸립니다.
2. 승인되면 파트너 센터 대시보드에서 나만의 **CID(고유 파트너 ID, 숫자)**
   를 확인할 수 있습니다. 이 숫자가 예약을 나에게 연결해주는 열쇠입니다.
3. 수수료 지급을 받으려면 은행 계좌 정보 등을 대시보드에 직접 입력하셔야
   합니다 — 이 부분은 민감한 금융 정보라 제가 대신 입력해드릴 수 없으니,
   본인이 로그인해서 진행해주세요.
4. 참고로 아고다 제휴 쿠키는 유지 기간이 **하루(24시간)** 로 꽤 짧습니다
   (방문자가 링크를 클릭한 뒤 24시간 안에 예약해야 수수료로 인정됩니다).
   수수료율이나 최소 지급액 같은 세부 조건은 시기·계정마다 달라질 수 있어서,
   정확한 수치는 로그인 후 대시보드에서 직접 확인해주세요.

**2) CID를 사이트에 연결하기**

`app.js` 맨 위 `CONFIG.agoda.cid`에 발급받은 CID 숫자를 그대로 넣기만
하면 됩니다.

```javascript
agoda: {
  cid: "1234567"  // 여기에 본인 CID를 넣으세요
}
```

이 값이 비어있는 동안(`cid: ""`)에는 지금까지처럼 빈 "광고 영역" 표시만
남고, 나머지 사이트 동작에는 전혀 영향이 없습니다. CID를 넣는 순간
자동으로 아고다 배너가 켜집니다.

**3) (선택) 나라·도시별 숙소 페이지로 바로 연결하기**

CID만 넣어도 배너는 동작하지만(아고다 홈으로 연결), 구글시트의 Countries·
Cities 탭에 아래 열을 추가해두면 방문자가 바로 그 도시/나라 숙소 목록
페이지로 이동해서 예약 전환율이 훨씬 좋아집니다.

| 탭 | 추가할 열 이름 | 예시 값 | 쓰이는 곳 |
|---|---|---|---|
| Countries | `agoda_country_slug` | `japan`, `thailand`, `vietnam` | 도시를 아직 안 고른 "국가 전체" 화면 |
| Cities | `agoda_slug` | `tokyo-jp`, `bangkok-th`, `hanoi-vn` | 특정 도시를 선택한 화면 |

슬러그(slug)는 아고다 웹사이트에서 그 도시/나라를 검색해서 나온 페이지의
주소에서 확인할 수 있습니다.

- 도시: `agoda.com/city/도쿄`를 검색하면 주소가
  `https://www.agoda.com/city/tokyo-jp.html`처럼 나오는데, 이 중
  `tokyo-jp` 부분이 `agoda_slug`입니다.
- 나라: `agoda.com/country/타이`를 검색하면 주소가
  `https://www.agoda.com/country/thailand/popular-hotels.html`처럼
  나오는데, 이 중 `thailand` 부분이 `agoda_country_slug`입니다.

두 열 다 선택 사항이고, 도시에 슬러그가 없으면 그 나라 슬러그로, 나라에도
없으면 아고다 홈으로 자동으로 대신 연결되니 안 채운 도시가 있어도
사이트가 깨지지 않습니다. 샘플 데이터(`data/sample-data.js`)에 도쿄·오사카·
하노이·다낭·방콕·치앙마이·일본·베트남·태국 예시가 미리 채워져 있으니
참고하세요.

**4) 제휴 링크 고지**

배너 자체에 "제휴 링크 · 예약하시면 트콤 가이드 제작에 도움이 돼요"라는 문구를
항상 함께 표시해서, 이 링크로 예약하면 운영자가 수수료를 받는다는 사실을
방문자에게 알리도록 해뒀습니다. 이런 경제적 이해관계 고지는 한국
공정거래위원회의 "추천·보증 등에 관한 표시·광고 심사지침"에서도 요구하는
사항이라 임의로 지우지 않으시길 권장드립니다.

## 15. 클룩(Klook) 렌터카 헤더 배너

헤더 아래 큰 광고 자리(#ad-slot-top)에는 클룩(Klook) 제휴 링크로 연결되는
고정 이미지 배너가 아고다 배너보다 먼저 표시됩니다. 아고다처럼 나라/도시에
따라 문구가 바뀌지는 않지만, 항상 같은 자리에서 클릭을 받을 수 있습니다.
영상 목록 아래 작은 광고 자리는 지금까지처럼 아고다 배너가 그대로 씁니다.

**1) 배너 이미지**

`images/klook-banner.svg` 파일이 실제 배너 이미지입니다. 클룩의 공식 로고나
브랜드 소재를 그대로 가져다 쓰는 대신, "클룩(Klook)"이라는 글자와 차량
아이콘을 이용해 이 사이트만의 배너로 새로 그렸습니다. 728×90 크기에 맞춰
그려져 있고, 벡터(SVG)라서 화면이 커도 흐려지지 않습니다.

디자인을 바꾸고 싶으면 이 SVG 파일을 직접 편집하거나(글자, 색상 등을 코드
에디터로 열어 수정), 원하는 이미지(PNG/JPG 등)로 통째로 교체하고 파일 이름만
같게 맞춰주면 됩니다. 다른 이름으로 바꾸고 싶으면 `app.js`의
`CONFIG.klook.bannerImage` 값도 함께 바꿔주세요.

**2) 링크(제휴 리다이렉트 URL) 연결하기**

`app.js` 맨 위 `CONFIG.klook.redirectUrl`에 클룩 파트너 센터
(affiliate.klook.com)에서 발급받은 나의 리다이렉트 링크를 그대로 붙여넣으면
됩니다. 지금은 아래 링크(렌터카 페이지로 연결)가 이미 들어가 있습니다.

```javascript
klook: {
  enabled: true,
  redirectUrl: "https://affiliate.klook.com/redirect?aid=89998&aff_adid=1425111&k_site=https%3A%2F%2Fwww.klook.com%2Fen-US%2Fcar-rentals%2F",
  bannerImage: "images/klook-banner.svg"
}
```

배너를 잠깐 끄고 싶으면 `enabled: false`로 바꾸면 됩니다. 그러면 헤더는
자동으로 다음 순위인 아고다 배너(CID가 설정되어 있다면), 그마저 없으면 빈
"광고 영역" 표시로 되돌아갑니다.

**3) 다른 제휴사/캠페인 링크로 바꾸기**

클룩 렌터카가 아니라 다른 카테고리(투어, 티켓 등)나 다른 제휴 프로그램
링크로 바꾸고 싶을 때도 `redirectUrl` 값만 새 링크로 바꿔주면 됩니다. 배너
이미지의 문구("클룩(Klook) 렌터카 예약하기")도 실제 연결되는 상품과
맞도록 `images/klook-banner.svg`를 함께 고쳐주는 걸 권장드립니다.

**4) 제휴 링크 고지**

배너 이미지 안에 "제휴 링크 · 예약하시면 트콤 가이드 제작에 도움이 돼요"라는
문구를 함께 넣어서, 아고다 배너와 마찬가지로 경제적 이해관계를 방문자에게
알리도록 해뒀습니다. `privacy.html`의 제7조(제휴 마케팅 링크 이용 안내)에도
클룩을 포함한 제휴 링크 전반에 대한 안내가 들어가 있습니다.

## 16. 구글 애널리틱스(GA4) 및 검색엔진 노출(SEO) 설정

**1) 구글 애널리틱스(GA4)**

측정 ID `G-54V354TPYY`로 방문 통계를 수집하도록 연결해뒀습니다. 실제
코드는 두 파일에 나뉘어 있습니다.

- `index.html`(과 `privacy.html`) `<head>`의 `<script async src="https://www.googletagmanager.com/gtag/js?id=G-54V354TPYY">`
  — 구글에서 제공하는 gtag.js 라이브러리를 불러옵니다.
- `analytics.js` — 실제 설정 로직입니다.

이 사이트는 이미 화면 하단에 쿠키 동의 배너(`cookie-consent.js`)가 있어서,
`analytics.js`는 **방문자가 배너에서 "동의"를 선택했을 때만** 실제로
애널리틱스 쿠키가 저장되도록 구글의 "동의 모드(Consent Mode v2)"로
연결해뒀습니다. "거부"를 선택했거나 아직 아무 것도 선택하지 않았다면
방문 기록이 저장되지 않고, 나중에 배너에서 "동의"로 바꾸는 순간 바로
반영됩니다. `privacy.html` 제6조에도 이 내용을 안내해뒀습니다.

측정 ID를 나중에 바꾸고 싶으면(다른 GA4 속성으로 옮기는 경우 등)
`analytics.js` 맨 위의 `MEASUREMENT_ID` 값과, `index.html`·`privacy.html`
두 곳의 `<script async src="...id=G-54V354TPYY">` 링크 속 ID를 함께
바꿔주면 됩니다.

애널리틱스가 정상적으로 연결됐는지 확인하려면, 사이트를 배포한 뒤
[Google 애널리틱스](https://analytics.google.com/) 좌측 메뉴의 "실시간"
보고서를 열어두고, 다른 브라우저(또는 시크릿 창)로 사이트에 접속해서
쿠키 동의 배너에서 "동의"를 눌러보세요. 잠시 후 실시간 보고서에 접속자
1명이 표시되면 정상 연결된 것입니다.

**2) 기본 SEO(검색엔진 최적화) 설정**

검색 결과와 카카오톡/페이스북 등에 공유했을 때 사이트가 제대로 보이도록
아래 항목들을 넣어뒀습니다.

- **메타 설명(description) / 제목** — `index.html`, `privacy.html`
  `<head>`의 `<meta name="description">`에서 검색 결과에 노출될 요약
  문구를 바꿀 수 있습니다.
- **Open Graph / 트위터 카드** — 카카오톡, 페이스북, 트위터(X) 등에
  링크를 공유했을 때 보이는 미리보기 이미지·제목·설명입니다. 미리보기
  이미지는 `images/og-image.jpg`(1200×630)이고, 브랜드 색상으로 새로
  그린 이미지라 언제든 원하는 이미지로 바꿔도 됩니다(같은 파일명으로
  덮어쓰거나, 다른 파일명으로 바꾸면 `og:image`/`twitter:image` 값도
  함께 바꿔주세요).
- **구글 검색 결과 맨 위에 뜨는 "사이트 이름"** — 검색 결과에서 제목 위에
  작게 표시되는 이름(지금은 "트립콤파니")은 `<meta property="og:site_name">`
  값을 바꾸면 바뀝니다. 다만 이건 구글이 여러 신호를 참고해서 알아서
  고르는 값이라, 바꿨다고 바로 반영되는 게 아니라 구글이 사이트를 다시
  크롤링한 뒤(보통 며칠~몇 주) 서서히 바뀝니다. 더 빨리 반영되길 원하면
  아래 3번 항목의 구글 서치 콘솔에서 "URL 검사 → 색인 생성 요청"을
  눌러 재크롤링을 요청할 수 있습니다(그래도 100% 즉시 반영을 보장하진
  않습니다).
- **파비콘** — 브라우저 탭에 보이는 작은 아이콘입니다. `favicon.ico`,
  `images/favicon.svg`, `images/apple-touch-icon.png`로 준비해뒀고,
  전부 하나의 원본(`images/favicon.svg`)에서 만든 것이라 로고를 새로
  만들면 이 파일들도 함께 바꿔주는 걸 권장드립니다.
- **canonical(대표 주소) 링크** — 지금은 `https://tripcompany.world/`로
  맞춰뒀습니다. 도메인을 바꾸거나 `www.` 유무가 달라지면 `index.html`·
  `privacy.html`의 `<link rel="canonical">`, `og:url`, `og:image`,
  `twitter:image`, `robots.txt`, `sitemap.xml`의 주소를 전부 새 도메인으로
  바꿔주세요(하나라도 예전 주소로 남아있으면 검색엔진이 혼동할 수
  있습니다).
- **구조화 데이터(JSON-LD)** — `index.html` `<head>`에 넣은
  `<script type="application/ld+json">` 블록입니다. 검색 결과에 사이트
  이름과 설명이 더 정확하게 표시되도록 돕는 용도라, 딱히 손댈 필요는
  없습니다.
- **robots.txt / sitemap.xml** — 사이트 최상위 폴더(`index.html`과
  같은 위치)에 두는 파일입니다. `robots.txt`는 검색엔진에게 "전체
  공개, sitemap 위치는 여기"라고 알려주고, `sitemap.xml`은 색인해도
  되는 페이지 목록(지도 페이지, 개인정보처리방침 페이지)입니다. 페이지를
  더 추가하면 `sitemap.xml`에도 같은 형식으로 추가해주세요. 참고로
  `update-location-*.html`(트콤 위치 업데이트용 페이지)은 일부러
  sitemap/robots에 넣지 않았습니다 — robots.txt는 누구나 볼 수 있는
  공개 파일이라, 거기에 그 주소를 적어두면 오히려 더 쉽게 찾아낼 수
  있기 때문입니다. 대신 그 페이지 자체에 `<meta name="robots"
  content="noindex, nofollow">`를 넣어 검색엔진이 알아서 무시하도록
  해뒀습니다.

**3) Google 서치 콘솔 / 네이버 서치어드바이저 등록 (직접 해주셔야 해요)**

여기까지는 사이트 안에서 할 수 있는 준비였고, 실제로 검색 결과에 노출되게
하려면 검색엔진 쪽에도 사이트를 등록해야 합니다. 계정 로그인이 필요한
부분이라 제가 대신 해드릴 수 없어서, 아래 단계를 직접 진행해주세요.

- **Google 서치 콘솔**: [search.google.com/search-console](https://search.google.com/search-console/)
  에서 소유자 인증(도메인 또는 URL 접두어 방식) 후, 왼쪽 메뉴의
  "Sitemaps"에 `https://tripcompany.world/sitemap.xml` 주소를 제출하세요.
  소유자 인증 과정에서 `<meta name="google-site-verification" ...>`
  태그를 발급해주면, `index.html` `<head>`의 "검색엔진 소유 확인(선택
  사항)" 주석 아래에 그대로 붙여넣고 다시 배포하면 됩니다.
- **네이버 서치어드바이저**: [searchadvisor.naver.com](https://searchadvisor.naver.com/)
  에서 사이트 등록 후 마찬가지로 사이트맵 주소를 제출하면, 네이버 검색에도
  더 빨리 반영됩니다. 여기서 발급하는 확인 태그도 같은 자리에 추가하면
  됩니다.

등록 직후 바로 검색 결과에 나타나지는 않고, 보통 며칠에서 몇 주 정도
걸립니다. 새 페이지를 추가했을 때도 이 두 콘솔에서 "URL 검사 → 색인 생성
요청"을 하면 조금 더 빨리 반영됩니다.

## 17. 트립닷컴(Trip.com) 호텔 예약 제휴 배너

영상 목록 아래 작은 광고 자리(inline)에는 트립닷컴 제휴 링크로 연결되는
고정 이미지 배너가 아고다 배너보다 먼저 표시됩니다. 아고다 승인 전까지는
이 자리가 빈 "광고 영역"으로만 보였는데, 트립닷컴으로 채워서 바로 수익화가
가능하도록 했습니다. 헤더 큰 자리는 지금처럼 클룩이 그대로 씁니다.

**1) 배너 이미지**

`images/tripcom-banner.svg` 파일이 실제 배너 이미지입니다. 클룩과
마찬가지로 트립닷컴의 실제 로고 대신, "트립닷컴 호텔 특가 예약" 문구와
호텔 건물 아이콘으로 이 사이트만의 배너를 새로 그렸습니다. 영상 목록 아래
자리(가로 100% · 세로 70px)에 맞춰 그려져 있고, 벡터(SVG)라 화면이 커도
흐려지지 않습니다.

디자인을 바꾸고 싶으면 이 SVG 파일을 직접 편집하거나 원하는 이미지로
통째로 교체하고 파일 이름만 같게 맞춰주면 됩니다. 다른 이름으로 바꾸고
싶으면 `app.js`의 `CONFIG.tripcom.bannerImage` 값도 함께 바꿔주세요.

**2) 링크(제휴 URL) 연결하기**

`app.js` 맨 위 `CONFIG.tripcom.redirectUrl`에 트립닷컴에서 발급받은 나의
제휴 링크를 그대로 붙여넣으면 됩니다. 지금은 아래 링크가 이미 들어가
있습니다.

```javascript
tripcom: {
  enabled: true,
  redirectUrl: "https://www.trip.com/t/mM69FZbSIW2",
  bannerImage: "images/tripcom-banner.svg"
}
```

배너를 잠깐 끄고 싶으면 `enabled: false`로 바꾸면 됩니다. 그러면 그
자리는 자동으로 다음 순위인 아고다 배너(CID가 설정되어 있다면), 그마저
없으면 빈 "광고 영역" 표시로 되돌아갑니다.

**3) 제휴 링크 고지**

배너 이미지 안에 "제휴 링크 · 예약하시면 트콤 가이드 제작에 도움이 돼요"라는
문구를 함께 넣어서, 아고다·클룩 배너와 마찬가지로 경제적 이해관계를
방문자에게 알리도록 해뒀습니다. `privacy.html`의 제7조(제휴 마케팅 링크
이용 안내)에도 트립닷컴을 포함한 제휴 링크 전반에 대한 안내가 들어가
있습니다.

## 18. 하단 채널별 최신 영상 3분할

지도 영역 아래, 푸터 바로 위에 "트콤 근황을 알려드림(여행하는트콤 최신
영상) / 광고 / 트콤 최신 여행 가이드(트립콤파니 최신 영상)" 3칸이
나란히 나오는 자리를 추가했습니다. 데스크탑에서는 가로로 3칸이
나열되고, 화면이 좁아지면(860px 이하, 지도 레이아웃이 세로로 바뀌는
지점과 동일) 세로로 쌓입니다.

**1) 최신 영상이 자동으로 바뀌는 원리**

두 영상 자리는 특정 영상 하나를 직접 지정해둔 게 아니라, 각 채널의
"업로드" 재생목록을 통째로 불러오는 방식입니다.

```html
<iframe src="https://www.youtube-nocookie.com/embed/videoseries?list=UUz4VpUpJdmIlWaUgAwIARGA" ...></iframe>
```

유튜브는 모든 채널마다 이 업로드 재생목록을 자동으로 만들어주는데, 주소가
채널 ID(`UC`로 시작)에서 앞 두 글자만 `UU`로 바꾼 값입니다. 이 재생목록은
최신 업로드가 맨 앞에 오도록 유튜브가 항상 자동으로 정렬해주기 때문에,
새 영상을 올리면 사이트를 다시 배포하지 않아도 방문자에게는 그 영상이
바로 보입니다. 지금 연결된 값은 다음과 같습니다.

| 채널 | 채널 ID | 업로드 재생목록 ID |
|---|---|---|
| 트립콤파니 | `UC0EQX5Z2TlaKeIw4O3ieZAQ` | `UU0EQX5Z2TlaKeIw4O3ieZAQ` |
| 여행하는트콤 | `UCz4VpUpJdmIlWaUgAwIARGA` | `UUz4VpUpJdmIlWaUgAwIARGA` |

채널을 새로 만들거나 바꾸게 되면, 그 채널 페이지 소스에서 채널 ID를 찾아
(또는 검색으로 "채널 핸들 channel id" 식으로 찾아) 위와 같이 `UC`를
`UU`로 바꾼 값을 `index.html`에서 해당 `<iframe src="...">`의 `list=`
뒷부분에 그대로 바꿔 넣으면 됩니다.

영상 모달(개별 영상 클릭 시 뜨는 재생 창)과 마찬가지로 `youtube.com`이
아니라 `youtube-nocookie.com` 도메인으로 불러와서, 방문자가 실제로
재생 버튼을 누르기 전까지는 추적 쿠키가 덜 설치되도록 해뒀습니다.

**2) 가운데 광고 자리**

지금은 트립닷컴 제휴 광고 코드(320×320, ID `S19768275`)가 실제로
들어가 있습니다. `index.html`에서 `class="latest-video-ad"`인
`<div>` 안의 `<iframe>`을 찾으면 됩니다.

```html
<iframe
  src="https://kr.trip.com/partners/ad/S19768275?Allianceid=10516094&SID=330926814&trip_sub1=%ED%95%98%EB%8B%A8"
  id="S19768275"
  width="320" height="320"
  frameborder="0" scrolling="no"
  style="width:320px;height:320px;border:none;"
  loading="lazy"></iframe>
```

다른 광고 코드로 바꾸고 싶으면 이 `<iframe>` 전체를 새 코드로 그대로
교체하면 됩니다(광고사가 준 `<iframe>`의 `width`/`height`/`style`은
손대지 마세요 — 크기를 임의로 늘리거나 줄이면 광고가 깨지거나 클릭
영역이 어긋날 수 있습니다). 애드센스 승인 전까지 다시 빈 자리로
되돌리고 싶으면, 이 `<iframe>`을 지우고 대신
`<div class="ad-slot"><span>광고 영역</span></div>`를 넣으면 헤더
광고 자리와 같은 점선 placeholder로 돌아갑니다.

**3) 가운데 광고 자리 크기**

가운데 칸은 양옆 영상과 달리 16:9 비율을 강제하지 않고, 구글 애드센스
등 실제 디스플레이 광고가 자주 쓰는 정해진 픽셀 크기를 그대로 담을 수
있도록 폭 최대 320px · 높이 최소 250px로 잡아뒀습니다. 그래서 아래처럼
자주 쓰이는 사각형 광고 크기들을 그대로 넣을 수 있습니다.

- **300×250**(중간 크기 직사각형) — 폭 320px 안에 그대로 들어갑니다.
- **320×320**(정사각형, 지금 트립닷컴 광고가 이 크기입니다) — 높이가
  250px보다 크지만, 높이는 "최소 250px"일 뿐 위로 막혀있지 않아서
  광고 코드가 그만큼 요청하면 자리도 함께 늘어나 잘리지 않습니다.
- **336×280** 같은 조금 더 큰 사각형은 폭이 320px를 넘어서므로, 이
  크기를 쓰고 싶으면 `style.css`의 `.latest-video-ad` 안 `max-width`
  값을 336px로 늘려주면 됩니다.

가운데 칸은 양옆 영상 칸과 달리 자기 크기만큼만 차지하고 위쪽 기준으로
정렬되기 때문에(`align-items: start`), 광고 높이가 영상 프레임보다
크거나 작아도 레이아웃이 틀어지지 않습니다.

## 19. 지역별 맞춤 제휴 광고 (영상 카드들 사이에 끼워 넣기)

도쿄에서는 "도쿄 디즈니랜드 입장권 예약하기", 오사카에서는 "오사카
유니버설 스튜디오 입장권 예약하기"처럼, **그 도시(또는 나라)를 보고
있을 때만** 나타나는 광고 카드를 오른쪽 영상 목록 안에 영상 카드들과
똑같은 생김새로 자연스럽게 섞어서 보여주는 기능입니다. 다른 지역에서는
전혀 표시되지 않고, 한 도시에 광고를 여러 개 걸어두면 볼 때마다 그중
하나를 무작위로 골라서 보여줍니다.

**등록 방법 — "LocalAds" 탭 새로 만들기**

구글시트에 "LocalAds"라는 새 탭을 만들고, 아래 다섯 칸을 첫 줄(헤더)에
그대로 적어주세요. 이 탭도 다른 탭들과 똑같이 File → 공유 → 웹에 게시
(Publish to web)에서 "쉼표로 구분된 값(.csv)" 형식으로 게시한 뒤, 나온
링크를 `app.js`의 `CONFIG.csv.localAds`에 붙여넣어야 실제로 켜집니다
(자세한 방법은 이 문서 맨 앞쪽 "웹 게시 + CSV로 무료로 계속 쓰기"
항목과 동일합니다). 링크를 안 넣으면 기능 자체가 꺼질 뿐 나머지는
평소처럼 작동합니다.

| 열 이름 | 내용 | 필수 여부 |
|---|---|---|
| `city_id` | 이 도시를 선택했을 때 적용 (Cities 탭의 city_id와 동일한 값) | 아래 country_code와 둘 중 하나 |
| `country_code` | city_id가 비어있을 때, 아직 도시를 고르지 않은 "나라 전체" 화면에 적용 (Countries 탭의 country_code와 동일한 값) | 아래 city_id와 둘 중 하나 |
| `local_ad_label` | 카드에 보일 문구 (예: `도쿄 디즈니랜드 입장권 예약하기`) | 필수 |
| `local_ad_url` | 클릭하면 이동할 제휴 링크 | 필수 |
| `local_ad_image` | 섬네일로 쓸 이미지 URL | 선택 — 비워두면 🎫 아이콘으로 대체 |

예시로 두 줄을 넣으면 이렇게 됩니다.

| city_id | country_code | local_ad_label | local_ad_url |
|---|---|---|---|
| `JP-TOKYO` | | 도쿄 디즈니랜드 입장권 예약하기 | (제휴 링크) |
| `JP-OSAKA` | | 오사카 유니버설 스튜디오 입장권 예약하기 | (제휴 링크) |

**한 도시에 여러 개 걸고 싶을 때**

같은 `city_id`로 줄을 여러 개 등록하면 됩니다 — 예를 들어 도쿄에
디즈니랜드 광고 한 줄, 도쿄 스카이트리 광고 한 줄을 각각 추가해두면,
도쿄를 볼 때마다 둘 중 하나가 무작위로 나타납니다(항상 둘 다 같이
나오지는 않고, 한 번에 하나만 보여줍니다). 개수 제한은 없으니 필요한
만큼 줄을 늘려서 쓰면 됩니다.

**local_ad_image 이미지 주소를 구하는 방법**

이 칸에는 이미지 파일이 아니라 이미지 "주소(URL)"를 적어야 합니다.
가장 확실한 방법은 이미지 파일을 저에게 보내서 사이트의 `images`
폴더 안에 직접 올려두는 것입니다 — 그러면 우리 도메인 안의 고정 주소
(예: `https://tripcompany.world/images/local-ads/tokyo-disneyland.jpg`)가
생기고, 그 주소를 이 칸에 붙여넣으면 됩니다. 이미지가 아직 없으면
비워둬도 되고(🎫 아이콘으로 자동 대체됩니다), 나중에 하나씩 채워
넣어도 됩니다.

크기는 카드 안에서 96×54px(16:9 비율)로 표시되고 꽉 채워서 잘리는
방식(`object-fit: cover`)이라 딱 맞을 필요는 없지만, 화면이 선명하게
나오려면 그보다 2~3배 큰 16:9 비율(예: 480×270, 640×360)로 준비하는
게 좋습니다.

`local_ad_label`과 `local_ad_url`이 둘 다 채워진 줄만 후보로 인정되고,
`city_id`와 `country_code`가 둘 다 비어있는 줄은 어디에도 매칭되지 않아
무시됩니다.

**어떻게 보이나요**

영상이 2개 이상이면 두 번째 영상 카드 뒤에, 1개뿐이면 그 뒤에 끼워
넣어서 영상들 사이에 섞여서 나타납니다. 영상이 아직 하나도 없는
지역이어도 이 광고 카드만은 따로 표시됩니다. 생김새는 영상 카드와
동일(섬네일 + 제목)하지만 살짝 다른 배경색과 "제휴 광고" 배지로 광고임을
분명히 표시하고, 클릭하면 영상 재생 모달이 아니라 `local_ad_url`이
가리키는 페이지로 새 탭에서 바로 이동합니다.

**도시와 나라를 함께 쓸 때**

한 나라 안에 도시별로 서로 다른 광고를 걸고 싶으면 그 도시들의
`city_id`로 줄을 각각 추가하면 되고(도쿄엔 디즈니랜드, 오사카엔
유니버설처럼), 도시를 아직 고르지 않은 "나라 전체" 화면에도 무언가
보여주고 싶으면 `city_id`는 비워두고 `country_code`만 채운 줄을 따로
추가하면 됩니다. 도시 화면에서는 항상 그 도시의 `city_id` 줄들만
후보가 되고, `country_code` 줄은 도시를 고르지 않은 화면에만 쓰입니다.

## 20. 클릭·조회 통계 (GA4 맞춤 이벤트)

이 사이트가 GA4로 보내는 맞춤 이벤트는 네 가지입니다.

| 이벤트 이름 | 언제 보내지나 | 무엇을 알 수 있나 |
|---|---|---|
| `affiliate_click` | 제휴 광고를 클릭했을 때 | 어떤 광고가 돈이 되는지 |
| `region_select` | 지도에서 나라/도시를 골랐을 때 | 어느 지역이 인기 있는지 |
| `video_open` | 영상 재생창을 열었을 때 | 어떤 영상이 실제로 재생되는지 |
| `share_click` | 패널의 "공유" 버튼을 눌렀을 때 | 어느 지역이 공유되는지 |

**1) `affiliate_click` — 광고 클릭**

클룩 헤더 배너, 아고다 배너(헤더·인라인), 트립닷컴 인라인 배너, 지역별
맞춤 광고 카드까지 — 이 네 가지 광고를 누가 클릭했는지 GA4에서 확인할
수 있습니다. 클릭할 때마다 `affiliate_click`이라는 이벤트가 GA4로
전송되고, 다음 세 가지 정보가 함께 딸려갑니다.

| 파라미터 | 값 | 의미 |
|---|---|---|
| `ad_network` | `klook` / `agoda` / `tripcom` / `local_ad` | 어느 광고인지 |
| `ad_placement` | `header` / `inline` / `video_list` | 화면 어느 자리인지 |
| `ad_label` | 예: `도쿄 숙소`, `도쿄 디즈니랜드 입장권 예약하기` | 그 순간 보여준 문구 |

**GA4에서 확인하는 방법**

왼쪽 메뉴 "보고서" → "참여도" → "이벤트"로 들어가면 이벤트 이름 목록에
`affiliate_click`이 나타납니다(방문자가 실제로 클릭을 한 번이라도 해야
목록에 뜨기 시작합니다). 그 이벤트를 클릭하면 총 클릭 수를 볼 수 있고,
`ad_network`·`ad_placement`·`ad_label`별로 나눠보고 싶으면 화면 오른쪽
위 "맞춤 보고서" 또는 "탐색" 메뉴에서 이 세 파라미터를 세부 항목(보조
측정기준)으로 추가하면 "어떤 광고를 얼마나 클릭했는지"를 표로 볼 수
있습니다. 바로 반영되지는 않고 보통 몇 시간 정도 걸리며, 방금 클릭한
걸 바로 확인하고 싶으면 "실시간" 보고서에서도 이벤트 수가 즉시 올라가는
걸 볼 수 있습니다.

**집계에서 빠지는 것**

하단 "채널별 최신 영상" 가운데 자리에 넣은 트립닷컴 iframe 광고는 이
통계에 잡히지 않습니다. 그 자리는 트립닷컴이 직접 제공하는 화면이 우리
페이지 안에 통째로 떠 있는 것이라, 브라우저 보안 정책상 그 안에서 무슨
클릭이 일어나는지는 우리 쪽 코드가 알 방법이 없기 때문입니다. 실제
`<a>` 링크로 되어 있는 나머지 네 광고 자리만 집계됩니다. 또한 쿠키
동의를 거부한 방문자의 클릭은 다른 모든 GA4 이벤트와 마찬가지로 실제
집계에는 반영되지 않습니다.

**2) `region_select` — 어느 지역을 골랐나**

방문자가 지도에서 나라나 도시를 고를 때마다 전송됩니다. "사람들이
어느 지역을 궁금해하는지"를 알 수 있어서, 다음에 어떤 지역 영상을
찍을지 정할 때 참고가 됩니다.

| 파라미터 | 값 | 의미 |
|---|---|---|
| `region_type` | `country` / `city` | 나라를 골랐는지, 도시를 골랐는지 |
| `region_name` | 예: `일본 · 오사카` | 고른 지역 이름 |
| `region_slug` | 예: `osaka` | 그 지역의 공유 주소에 쓰이는 값 |
| `select_source` | `map` / `random` / `deep_link` | 지도를 직접 클릭했는지, "랜덤 여행지" 버튼이 골라준 건지, 공유 링크로 바로 들어온 건지 |

`select_source`를 꼭 함께 보세요. `random`은 방문자가 그 지역을 찾은
게 아니라 버튼이 무작위로 골라준 것이고, `deep_link`는 우리가 뿌린
링크를 타고 들어온 것이라, 순수하게 "방문자가 관심 있어서 직접 찾아본
지역"만 보려면 `map`만 걸러서 보면 됩니다.

참고로 세계지도에서 도시 점을 바로 클릭하면 나라가 먼저 선택되고 그
다음 도시가 선택되므로 이벤트가 두 번(`country` 한 번, `city` 한 번)
전송됩니다. 도시 인기 순위를 볼 때는 `region_type`이 `city`인 것만
보시면 됩니다.

**3) `video_open` — 어떤 영상이 재생됐나**

영상 카드를 눌러 재생창이 열릴 때마다 전송됩니다. 유튜브 자체 통계와
달리 "이 사이트를 통해 어떤 영상이 재생됐는지"를 볼 수 있습니다.

| 파라미터 | 값 | 의미 |
|---|---|---|
| `video_title` | 영상 제목 | 어떤 영상인지 |
| `video_id` | 유튜브 영상 ID | 영상 식별용 |
| `video_channel` | `트립콤파니` / `여행하는트콤` | 어느 채널 영상인지 |
| `region_name` | 예: `일본 · 오사카` | 어느 지역 화면에서 재생했는지 |
| `open_source` | `video_list` / `related_list` | 오른쪽 목록에서 열었는지, 재생창 아래 "이어서 볼 영상"에서 이어 본 건지 |

`open_source`가 `related_list`인 비율이 높으면 방문자들이 영상을 연달아
보고 있다는 뜻이라, 체류시간 측면에서 좋은 신호입니다.

**4) `share_click` — 공유 버튼**

패널 제목 옆 "공유" 버튼을 눌렀을 때 전송되며, `region_slug`(어느 지역을
공유했는지)와 `share_method`(`web_share`는 휴대폰 기본 공유창,
`clipboard`는 PC에서 주소 복사)가 함께 전송됩니다.

## 21. 최근 업데이트 지역 "NEW" 배지

지도에서 최근에 영상이 새로 올라온 지역(최대 3곳)에 자동으로 빨간 "N"
배지를 붙여주는 기능입니다. 순위를 매기려면 그 영상이 "언제" 추가됐는지
알아야 하므로, **Videos 탭에 `added_date`라는 칸을 하나 추가**해야
합니다.

**Videos 탭에 추가할 칸**

| 칸 이름 | 값 예시 | 설명 |
|---|---|---|
| `added_date` | `2026-09-11` | 그 영상을 지도에 추가한 날짜 (연-월-일) |

기존 영상들은 이 칸을 비워둬도 되고, 나중에 채워도 됩니다. 비어있는
영상은 그냥 "최근 순위" 계산에서 빠질 뿐 나머지 표시(영상 목록, 광고
등)에는 전혀 영향이 없습니다. 앞으로 새 영상을 등록할 때마다 그날
날짜를 이 칸에 적어주시면 배지가 자동으로 갱신됩니다.

**어떻게 계산되는지**

각 영상의 `added_date` 중 가장 최근 날짜를 기준으로, 지역(도시 또는
나라)별로 "가장 최근에 영상이 추가된 날짜"를 구한 뒤 최신순으로 정렬해서
상위 3곳까지 배지를 붙입니다. 세부 규칙은 다음과 같습니다.

- 도시가 하나로 특정되는 영상은 그 도시 점에 배지가 붙습니다.
- 도쿄·오사카처럼 여러 도시를 비교하는 영상은 등장하는 도시들 각각의
  후보에 포함됩니다.
- 나라 전체를 다루는 영상(예: 싱가포르처럼 Cities 탭에 도시가 등록되지
  않은 나라)은 그 나라의 지도 점에 배지가 붙습니다. 다만 Cities 탭에
  도시가 이미 등록되어 있는 나라(한국, 일본 등)의 나라 단위 영상은
  배지를 붙일 마땅한 점이 하나로 정해지지 않으므로 계산에서 제외됩니다.
- 너무 오래된 업데이트까지 "최근"으로 잡히지 않도록, 30일이 지난
  지역은 순위 안에 들어도 자동으로 제외됩니다.

이 세 가지 숫자(최대 지역 수 3곳, 기준 30일, 기능 켜고 끄기)는
`app.js` 맨 위쪽 `CONFIG.newBadge` 값에서 조절할 수 있습니다.

```js
newBadge: {
  enabled: true,      // false로 바꾸면 배지 기능 전체를 끕니다
  maxLocations: 3,    // 최대 몇 곳까지 배지를 붙일지
  withinDays: 30       // 며칠 이내 업데이트만 "최근"으로 볼지
}
```

배지가 붙은 지도 점에 마우스를 올리면(모바일은 탭하면) 지역 이름 뒤에
" · NEW"가 함께 표시되고, 지도 왼쪽 아래 범례에도 배지 모양과 함께
"최근 업데이트" 설명이 추가되어 있습니다.

**영상 목록에도 NEW 표시**

오른쪽 영상 목록 패널에서도, `added_date`가 최근(기본 30일 이내)인
영상 카드는 썸네일 위에 "NEW" 배지가 붙습니다. 이건
지도 배지와 달리 "최대 3곳"이라는 개수 제한이 없습니다 — 지도는 점이
너무 많아지면 복잡해 보이지만, 영상 목록은 스크롤해서 보는 방식이라
기간(`withinDays`) 안에 든 영상은 모두 표시해도 괜찮기 때문입니다.
같은 `added_date` 칸과 `CONFIG.newBadge.withinDays` 설정을 그대로
공유하므로, 칸만 채워두면 지도와 영상 목록 양쪽에 자동으로 반영됩니다.

## 22. 특정 도시/나라를 바로 선택된 상태로 여는 링크 (`?region=`)

`https://tripcompany.world/map?region=osaka`처럼 주소 끝에
`?region=도시또는나라이름`을 붙이면, 그 페이지에 처음 들어왔을 때부터
해당 도시(또는 나라)가 이미 선택된 화면으로 바로 열립니다. 유튜브
영상 설명란이나 SNS 게시물에서 "오사카 영상 더 보기"처럼 특정 지역으로
바로 연결하고 싶을 때 씁니다.

**사용법**

주소 끝에 `?region=` 다음에 아래 값 중 하나를 넣으면 됩니다(대문자/
소문자는 구분하지 않습니다).

- 도시 이름(영문, `city_id`에서 국가 코드를 뺀 부분): 예) `osaka` →
  오사카, `tokyo` → 도쿄
- 도시 전체 `city_id`: 예) `jp-osaka`
- Cities 탭에 등록해둔 `agoda_slug`: 예) `osaka-jp`
- 위 방법으로 도시를 못 찾았을 때는, Countries 탭에 등록해둔
  `agoda_country_slug`로 나라 전체 화면을 엽니다: 예) `japan` → 일본
  국가 전체 화면

찾는 값이 하나도 없으면 에러 없이 그냥 평소 첫 화면이 보입니다. 새로
도시를 추가할 때 이 기능을 위해 구글시트에 따로 뭘 채울 필요는
없습니다 — 이미 있는 `city_id`(그리고 있다면 `agoda_slug`/
`agoda_country_slug`)를 그대로 재사용하는 방식이라, 도시를 등록하는
순간부터 그 도시 이름으로 바로 링크를 쓸 수 있습니다.

**주소가 `/map`으로 시작해도 되는 이유**

이 사이트에는 실제로 `/map`이라는 파일이 없지만, 프로젝트 폴더에 있는
`_redirects` 파일이 Netlify에게 "`/map`으로 들어오면 `index.html`
내용을 대신 보여줘(주소창은 그대로 유지)"라고 알려줍니다. 그래서
`/map?region=osaka`든 그냥 `/?region=osaka`든 둘 다 똑같이 동작합니다.
이 사이트를 다른 곳으로 옮기거나 Netlify Drop이 아닌 다른 방식으로
배포할 일이 생기면, `_redirects` 파일도 반드시 함께 올려야 이 기능이
계속 동작합니다(파일이 없으면 `/map` 주소 자체가 404가 됩니다 —
`/?region=osaka` 형태는 `_redirects` 없이도 그대로 동작합니다).

**주소창이 선택한 지역을 따라갑니다**

방문자가 지도에서 도시를 고를 때마다 주소창도 그 도시의 주소
(`?region=osaka`)로 자동으로 바뀝니다. 그래서 방문자가 주소창을 그대로
복사해서 친구에게 보내도, 받은 사람이 똑같은 화면으로 들어오게 됩니다.

브라우저 방문 기록을 쌓지 않는 방식(`history.replaceState`)을 썼기
때문에, 유튜브에서 넘어온 방문자가 뒤로가기를 누르면 도시를 하나씩
거슬러 올라가지 않고 곧바로 유튜브로 돌아갑니다. 또 주소를 다시 쓸 때
`utm_source` 같은 유입 파라미터는 일부러 지웁니다 — 유입 통계는 페이지가
열리는 순간 GA4가 이미 기록해뒀고, 그대로 남겨두면 방문자가 그 주소를
공유했을 때 남의 유입까지 내 채널 유입으로 잘못 집계되기 때문입니다.

**공유 버튼**

나라나 도시를 고르면 오른쪽 영상 패널 제목 옆에 "공유" 버튼이 나타납니다.
휴대폰에서는 카카오톡·메시지 등으로 바로 보낼 수 있는 기본 공유창이
뜨고(Web Share API), 그 기능이 없는 PC 브라우저에서는 주소가 클립보드에
복사되면서 버튼 글자가 잠깐 "복사됨!"으로 바뀝니다. 누를 때마다 GA4로
`share_click` 이벤트도 함께 전송됩니다(README 20번 항목).

참고로 나라 주소는 Countries 탭의 `agoda_country_slug`(예: `japan`)를
쓰고, 그 칸이 비어있는 나라는 국가 코드 숫자(예: `702`)가 대신 들어갑니다.
주소를 예쁘게 만들고 싶으면 그 칸만 채워두시면 됩니다(원래 아고다 배너용
칸이라, 채워두면 배너 연결도 함께 좋아집니다).

## 23. 첫 화면이 빨리 뜨게 하는 데이터 임시 저장(캐시)

구글시트 CSV는 방문할 때마다 새로 받아오는데, 구글 쪽 응답이 느린 날에는
지도에 점이 찍히기까지 몇 초가 걸리기도 합니다. 그래서 한 번 받아온
데이터를 방문자 브라우저에 저장해뒀다가, 다음 방문 때는 **일단 저장해둔
사본으로 화면을 즉시 띄우고, 최신 데이터는 뒤에서 조용히 받아와 바꿔치기**
하도록 해뒀습니다.

**시트를 고치면 언제 반영되나요?**

그 방문 안에서 바로 반영됩니다. 캐시는 "첫 화면을 빨리 띄우기 위한 임시
사본"일 뿐이고, 최신 데이터를 받아오는 동작은 예전과 똑같이 매번
실행되기 때문입니다. 그래서 방문자가 보는 순서는 이렇습니다.

1. (재방문이면) 저장해둔 사본으로 지도가 즉시 뜸 — 기다림 없음
2. 1~2초 뒤 최신 데이터가 도착하면 내용이 조용히 최신으로 바뀜

이때 방문자가 이미 고른 나라/도시와 보고 있던 지도 위치는 그대로
유지되므로, 보던 화면이 갑자기 튀지 않습니다.

**덤으로 생긴 장점**

최신 데이터를 받아오는 데 실패해도(구글시트 점검, 잠깐의 네트워크 문제
등) 저장해둔 사본이 있으면 에러 화면 대신 지도가 그대로 동작합니다.
예전에는 이런 상황에서 "지도를 불러오지 못했습니다" 화면이 떴습니다.

**세부 설정과 주의점**

- 저장 위치는 방문자 브라우저 안(로컬 스토리지)이고, 저장하는 내용은
  구글시트에 적힌 공개 정보(나라·도시·영상 목록)뿐입니다. 방문자 개인에
  관한 정보는 저장하지 않습니다(`privacy.html` 제6조에도 안내해뒀습니다).
- 하루가 지난 사본은 자동으로 버리고 처음부터 새로 받아옵니다
  (`app.js`의 `DATA_CACHE_MAX_AGE_MS`).
- 시크릿 모드처럼 저장이 안 되는 환경에서는 조용히 캐시 없이 예전과
  똑같이 동작합니다.
- 나중에 시트 구조를 크게 바꿔서 예전 사본을 무시하게 만들고 싶으면,
  `app.js`의 `DATA_CACHE_KEY` 값 끝의 `v1`을 `v2`로 올리면 됩니다.
- 샘플 데이터(`CONFIG.dataSource = "sample"`)로 테스트할 때는 저장하지
  않습니다.

참고로 지도의 국경 데이터(CDN에서 받아오는 파일)는 따로 저장하지
않습니다 — 브라우저가 알아서 캐시해주는 파일이라 이미 재방문 시 거의
즉시 불러와집니다.

## 24. 지도 위 도시 검색 & 밀도에 맞춘 자동 배율

지도 왼쪽 위 "내 위치" 버튼 아래에 도시 검색창이 있습니다. 도시가 늘어날수록
지도에서 눈으로 찾기가 번거로워지기 때문에 넣은 기능입니다.

**어떻게 찾아지나**

한글 이름, 영문 이름, 나라 이름 아무거나로 찾을 수 있습니다(대소문자 구분
없음).

| 입력 예 | 찾아지는 것 |
|---|---|
| `오사` | 오사카 (한글 이름) |
| `osaka` | 오사카 (`city_id`의 국가 코드 뒷부분) |
| `osaka-jp` | 오사카 (Cities 탭 `agoda_slug`) |
| `일본` | 일본에 등록된 도시 전부 |

이름이 검색어로 **시작하는** 도시가 중간에 걸린 도시보다 먼저 나오고, 같은
조건이면 영상이 있는 도시가 먼저 나옵니다. 아직 영상이 없는 도시(지도에
흰 점으로 표시되는 "준비중")도 결과에 함께 나오되 "영상 준비중"이라고
표시됩니다 — 실제로 그 지역을 찾는 사람이 있다는 뜻이라 숨기지 않았습니다.
키보드 위/아래 방향키와 엔터로도 고를 수 있습니다.

**밀도에 맞춰 배율이 자동으로 정해집니다**

검색 결과를 고르거나, 공유 링크(`?region=`)로 들어왔거나, "랜덤 여행지"
버튼으로 도시가 뽑혔을 때 — 그 도시를 얼마나 확대해서 보여줄지는 고정값이
아니라 **주변에 다른 도시가 얼마나 가까이 있는지**에 따라 매번 다르게
계산됩니다.

- 오사카·교토·고베처럼 도시들이 30~40km 간격으로 붙어있는 곳 → 점들이
  서로 구분될 만큼 바짝 확대
- 미국처럼 도시 사이가 수백~수천 km인 곳 → 바짝 당겨봐야 점 하나만 덩그러니
  남아 위치 감이 안 잡히므로, 주변 지역이 함께 보이도록 넓게

계산 방식은 "가장 가까운 이웃 도시가 화면에서 최소 70픽셀 떨어져 보이는
배율을 찾는다"입니다. 이웃이 가까우면 자동으로 많이 확대되고, 멀면 자동으로
넓어집니다. 실제 좌표로 계산해보면 이렇게 나옵니다.

| 도시 | 가장 가까운 이웃까지 | 자동 배율 |
|---|---|---|
| 오사카 | 28km (고베) | 8 (최대) |
| 교토 | 43km (오사카) | 7.7 |
| 도쿄 | 360km | 4.6 |
| 뉴욕 | 306km (보스턴) | 4.8 |
| 로스앤젤레스 | 2,804km | 4 (최소) |

두 숫자로 조절할 수 있습니다(`app.js`의 `CONFIG.map`).

```js
cityFocusSeparationPx: 70,  // 이웃 도시와 최소 이만큼 떨어져 보이게 (키우면 전체적으로 더 확대)
cityFocusMinZoom: 4         // 아무리 외딴 도시여도 이보다 더 축소하지는 않음
```

참고로 지도 자체의 최대 배율은 `CONFIG.map.maxZoom`(현재 8)이라, 도시들이
아주 붙어있어도 그 이상은 확대되지 않습니다. 지금 데이터 기준으로는 간사이
지역도 최대 배율에서 점들이 56픽셀쯤 떨어져 보여서 구분에 문제는 없습니다.

"랜덤 여행지" 버튼은 뽑힌 나라에 보여줄 도시가 있으면 그 도시를 위 방식대로
보여주고, 싱가포르처럼 Cities 탭에 도시가 없는 나라가 뽑히면 지금까지처럼
나라 전체를 화면에 맞춰줍니다. 지도에서 점을 직접 클릭할 때는 이미 그 점을
보고 있는 상황이라, 화면이 갑자기 움직이지 않도록 일부러 지도를 건드리지
않습니다.

**검색어 통계**

방문자가 검색해서 도시를 고르면 GA4로 `city_search` 이벤트가, 두 글자
이상 쳤는데 결과가 하나도 없으면 `city_search_no_result` 이벤트가
전송됩니다. 특히 후자는 "사람들이 찾는데 아직 우리한테 없는 지역"을
알려주므로, 다음에 어디 영상을 만들지 정할 때 참고하기 좋습니다
(README 20번 항목의 다른 이벤트들과 같은 자리에서 확인할 수 있습니다).

## 25. 지역을 옮길 때 지도가 빈 화면으로 보이던 문제

예전에는 먼 지역으로 이동할 때 나라 도형이 사라진 빈 지도를 가로질러
날아간 뒤, 도착해서야 도형이 다시 나타났습니다(도시 점만 둥둥 떠다니는
것처럼 보였습니다).

**왜 그랬나**

이 지도에는 배경 타일 이미지가 없고 나라 도형을 SVG로 직접 그립니다.
그런데 지도 라이브러리(Leaflet)는 성능을 위해 **지금 화면과 그 주변 약간
(기본값: 화면 크기의 10%)만 미리 그려두고**, 화면이 움직이는 동안에는 이미
그려둔 그림을 밀거나 늘릴 뿐 새로 그리지는 않습니다. 다시 그리는 건 이동이
완전히 끝난 뒤입니다.

그래서 멀리 날아가는 동안에는 "아직 그려지지 않은 영역"을 지나가게 되어
도형이 사라진 것처럼 보였습니다. 도시 점(마커)은 도형과 달리 각각 독립된
요소라 계속 따라다녔고, 그래서 점만 떠다니는 모습이 됐습니다.

**어떻게 고쳤나**

두 가지를 함께 적용했습니다.

1. 미리 그려두는 여유분을 기본값 0.1에서 **1.5로 크게 늘렸습니다**
   (`app.js`의 `MAP_RENDERER_PADDING`). 화면 크기의 150%만큼 바깥까지 미리
   그려두므로, 웬만한 짧은 이동은 이동하는 도중에도 도형이 계속 보입니다.
2. 그 여유분을 벗어날 만큼 먼 이동은 **아예 날아가지 않습니다.** 대신 아주
   짧게(0.16초) 화면을 흐렸다가 목적지에서 다시 선명해지게 했습니다
   (`jumpMapWithFade`). 빈 지도를 가로지르는 모습 자체가 없어집니다.

이 판단은 `moveMapTo()`가 자동으로 합니다 — 가까우면 부드럽게 날아가고,
멀거나 많이 축소되는 이동이면 흐림 전환을 씁니다. 검색·공유 링크·랜덤
여행지·"내 위치" 버튼 등 지도를 움직이는 모든 기능이 이 함수를 거칩니다.

**조절하고 싶다면**

- `MAP_RENDERER_PADDING`(기본 1.5): 키우면 더 먼 거리까지 날아가는
  애니메이션을 유지하지만, 그만큼 한 번에 그리는 도형이 많아져 느려질 수
  있습니다.
- `MAP_FADE_MS`(기본 160): 흐려졌다 돌아오는 시간(밀리초)입니다.
- 흐림 정도는 `style.css`의 `#map.is-map-fading { opacity: 0.15; }`에서
  바꿀 수 있습니다.

## 26. 나라 클릭이 전혀 반응하지 않던 문제 (수정 완료)

23번 항목의 "데이터 임시 저장(캐시)" 기능을 넣으면서 생긴 문제로, 나라를
클릭해도 아무 반응이 없고 지도 색깔도 계속 회색으로만 보이는 상태가
됐습니다.

**왜 그랬나**

지도 테두리(국경 도형)와 나라/도시/영상 데이터(구글시트)는 서로 다른
곳에서 따로 불러옵니다. 그런데 "지도 테두리부터 최대한 빨리 보여주자"는
생각으로 지도 테두리가 도착하는 즉시 `renderWorld()`를 실행해서 나라마다
클릭·마우스오버 이벤트를 걸어뒀는데, 하필 이 시점엔 아직 구글시트 데이터가
도착하기 전이라 "이 나라에 영상이 있는지" 자체를 판단할 수 없는 상태였습니다.
그래서 모든 나라가 "영상 없음"으로 잘못 판단되어 클릭 이벤트가 아예
연결되지 않은 채로 지도가 만들어졌고, 나중에 실제 데이터가 도착해도 이미
만들어진 지도 도형에 이벤트를 다시 걸어주는 코드가 없어서 계속 반응이
없었습니다(색깔이 계속 회색이었던 것도 같은 이유입니다).

**어떻게 고쳤나**

"이 나라에 영상이 있는지"를 지도를 처음 그릴 때 딱 한 번만 확인하지 않고,
클릭·마우스오버·툴팁이 실제로 일어나는 바로 그 순간에 매번 다시 확인하도록
`renderWorld()`를 고쳤습니다. 이렇게 하면 데이터가 지도 테두리보다 먼저
오든 나중에 오든 항상 정확하게 동작합니다. 또한 데이터가 도착했을 때
지도 색깔을 다시 칠하는 코드(`renderLoadedData()`)가 빠져 있던 것도 함께
추가해서, 첫 방문(캐시 없음)에도 영상이 있는 나라가 초록색으로 정확히
표시되도록 했습니다.

실제 Leaflet 지도 라이브러리는 이 환경에서 CDN 접근이 막혀 있어 직접 켜볼
수 없어서, `app.js`를 그대로 불러와 실행하는 자동화 테스트로 문제를
재현하고(수정 전 실패 → 수정 후 통과) 수정을 검증했습니다.

## 27. 도시를 어떤 방법으로 골라도 항상 같은 방식으로 확대해서 보여주기

예전에는 도시를 "고르는 방법"에 따라 화면이 다르게 동작했습니다. 도시 검색·
랜덤 여행지·공유 링크(`?region=`)로 도시를 고르면 그 도시로 적당히
확대됐지만, 지도 위 도시 점을 **직접 클릭**했을 때는 화면이 전혀 움직이지
않고 오른쪽 패널 내용만 바뀌었습니다.

**어떻게 고쳤나**

지도 위 도시 점을 클릭했을 때도 검색·랜덤과 똑같이 `focusCityOnMap()`을
호출하도록 통일했습니다. 세계지도에서 아직 나라를 고르지 않은 상태로 도시
점을 클릭한 경우엔, 나라 전체로 한 번 맞추고 다시 도시로 확대하며 화면이
두 번 움직이는 일이 없도록(다른 기능들과 동일하게) 나라 이동은 건너뛰고
곧바로 도시로 확대합니다. 이미 나라를 선택해서 그 나라의 도시 점들이 보이는
상태에서 클릭한 경우엔 나라 이동 없이 바로 도시로 확대합니다.

**확대 범위를 전체적으로 더 넓게 조정**

24번 항목의 밀도 기반 자동 줌(`zoomForCity`)이 도시로 확대했을 때 화면을
너무 바짝 당겨서 주변 지역 맥락이 잘 안 보인다는 의견이 있어서, 기준값을
절반으로 낮췄습니다(`CONFIG.map.cityFocusSeparationPx` 70→35,
`cityFocusMinZoom` 4→3). 밀도에 따라 도시마다 확대 정도가 달라지는 방식은
그대로 유지하면서, 전체적으로 줌이 한 단계(zoom -1, 화면에 보이는 면적은
2배) 정도 더 넓어졌습니다. 더 넓게/좁게 조절하고 싶으면 이 두 값을 함께
줄이거나 늘리면 됩니다(둘을 같은 비율로 바꿔야 "붐빈 도시일수록 더
확대"라는 원래 성질이 유지됩니다).

## 28. 지도 점에 마우스를 올리면 영상 개수도 함께 표시

지도 위 도시(또는 도시가 따로 없는 나라) 점에 마우스를 올렸을 때, 이제
이름 옆에 "영상 3개" 또는 아직 영상이 없으면 "영상 준비중"이 함께
표시됩니다. 도시 검색 결과 목록에서 쓰던 표현과 통일했습니다
(`videoCountLabel()` 함수, `app.js`).

## 29. 도시 검색창 길이 줄이기

검색창(`style.css`의 `.map-search`)이 필요 이상으로 길어 보여서, 지금
등록된 지명 중 가장 긴 "상트페테르부르크"(8자)를 입력해도 글자 한두 개
정도는 더 들어갈 여유만 남도록 줄였습니다.

실제 폰트(Pretendard/Apple SD Gothic Neo 계열)로 렌더링해서 글자 폭을
직접 재본 뒤 계산한 값으로, "상트페테르부르크"를 입력하면 입력창 안에
글자 1.5개 정도의 여유 공간이 남습니다. 검색 아이콘·지우기(×) 버튼·여백을
모두 포함한 전체 너비는 260px → 208px로 줄었습니다.

나중에 이보다 더 긴 지명을 등록하게 되면 `.map-search`의 `width` 값을
조금 늘려주면 됩니다.

## 30. 도시별 상세 가이드 페이지 (`city.html`) — 준비 단계

지도(`index.html`)와는 별개로, 도시 하나를 골라 숙소·투어·예산·FAQ까지
한 페이지에서 보여주는 **도시 가이드 페이지**를 새로 추가했습니다.
`city.html`과 `city.js` 두 파일이 새로 생겼고, 기존 `index.html` /
`app.js` / `style.css`는 이번에 전혀 손대지 않았습니다 — 지도에는 아직
이 페이지로 가는 링크가 어디에도 없습니다.

**아직 공개용이 아닙니다.** `city.html`의 `<meta name="robots">` 태그가
`noindex, nofollow`로 되어 있어서 검색엔진에 잡히지 않고, 지도 어디에도
연결돼 있지 않습니다. 실제로 오픈할 준비가 되면 (1) 이 robots 태그를
지우고, (2) 지도의 도시 정보 패널 같은 곳에 "상세 가이드 보기" 링크를
추가하면 됩니다. 지금은 아래 주소로 직접 열어서 미리 확인하는 용도입니다.

```
https://tripcompany.world/city.html?id=도시ID     (예: ?id=JP-TOKYO)
```

`?id=` 없이 그냥 열거나 아직 데이터를 하나도 안 채운 도시로 열면, 완성됐을
때 느낌을 바로 볼 수 있도록 "상하이" 예시 내용으로 채워서 보여줍니다(실제
사이트에 올라가는 내용이 아니라 미리보기 전용입니다).

**기존 시트를 그대로 재사용합니다.** Countries / Cities / Videos / LocalAds
탭은 새로 만들 필요 없이 지도에서 쓰던 것을 그대로 가져다 씁니다. 영상
목록도 Videos 탭의 `city_id`(콤마로 여러 도시 지정 가능)를 그대로
기준으로 삼습니다. 다만 영상 카드에 한두 문장 요약을 붙이고 싶으면 Videos
탭에 `summary_ko`라는 열을 하나 추가하면 됩니다 — 없어도 나머지는 그대로
작동합니다.

**새로 만들어야 하는 탭 다섯 개**

구글시트(지도와 같은 문서)에 아래 다섯 개 탭을 새로 만들고, 각각 File →
공유 → 웹에 게시(Publish to web)에서 "쉼표로 구분된 값(.csv)" 형식으로
게시한 뒤 나온 링크를 `city.js` 맨 위 `CONFIG.csv`의 해당 칸에 붙여넣으면
됩니다. 다섯 개 모두 비워둬도 에러 없이 동작하고(해당 도시가 "상하이"면
예시 내용, 다른 도시면 "준비 중이에요" 안내), 하나씩 채울 때마다 그
섹션만 실제 내용으로 바뀝니다.

**CityPages** — 도시 하나당 한 줄, 히어로 영역과 FAQ 문서 주소를 담습니다.

| 열 이름 | 내용 | 필수 여부 |
|---|---|---|
| `city_id` | Cities 탭의 city_id와 동일 (예: `JP-TOKYO`) | 필수 |
| `hero_tagline` | 히어로 큰 제목 아래 한 줄 소개 문구 | 선택 |
| `best_season` | 최적 여행 시기 (예: `3~5월 · 9~11월`) | 선택 |
| `flight_time` | 비행 시간 (예: `인천에서 2시간 10분`) | 선택 |
| `currency_code` | 통화 코드 (예: `CNY`) | 선택 — currency_name_ko와 함께 있어야 표시됨 |
| `currency_name_ko` | 통화 한글명 (예: `위안`) | 선택 — currency_code와 함께 있어야 표시됨 |
| `price_level` | 물가 수준 — `저렴`/`중간`/`비쌈` 등 원하는 단어를 그대로 | 선택 |
| `faq_doc_url` | FAQ용 구글독스 "웹에 게시" 링크 (아래 항목 참고) | 선택 |

**CityStay** — 지역별 숙소 제안 카드 (지역 개수만큼 줄을 추가)

| 열 이름 | 내용 | 필수 여부 |
|---|---|---|
| `city_id` | 대상 도시 | 필수 |
| `tier` | 카드 위에 붙는 짧은 등급 표시 (예: `가성비`/`중급`/`럭셔리`) | 선택 |
| `area_name` | 지역/동네 이름 (예: `인민광장 지역`) | 필수 |
| `transit_note` | 교통·위치 한 줄 설명 | 선택 |
| `price_range` | 1박 가격대 (예: `10~18만원대`) | 선택 |
| `comment` | 트립콤파니가 직접 쓰는 코멘트 | 선택 |

이 카드들은 "이런 지역들이 있다"는 소개와 코멘트만 보여주고, 예약 버튼은
카드마다 따로 두지 않습니다 — 아래 캐비엇 참고. (예전 버전에 있던
`link_url` 칸은 이제 안 씁니다. 이미 채워두셨어도 무시될 뿐이라
그대로 두셔도 되고, 지우셔도 됩니다.)

**CityTours** — 투어·액티비티 순위 카드 (순위만큼 줄을 추가)

| 열 이름 | 내용 | 필수 여부 |
|---|---|---|
| `city_id` | 대상 도시 | 필수 |
| `rank` | 순위 숫자 (1, 2, 3…) — 이 숫자 기준으로 정렬됩니다 | 필수 |
| `name` | 액티비티 이름 | 필수 |
| `price_from` | 시작 가격 (예: `4.9만원~`) | 선택 |
| `comment` | 왜 이 순위인지, 트립콤파니가 직접 쓰는 코멘트 | 선택 |
| `link_url` | 예약 링크 | 선택 — 비우면 "예약" 버튼 자체가 안 보임 |

**CitySpots** — 시간대별 추천 장소

| 열 이름 | 내용 | 필수 여부 |
|---|---|---|
| `city_id` | 대상 도시 | 필수 |
| `timeslot` | `아침`/`오후`/`저녁`/`밤` 중 하나 (이 네 단어를 쓰면 전용 아이콘이 붙고, 다른 단어를 써도 카드 자체는 만들어집니다) | 필수 |
| `place_name` | 장소 이름 | 필수 |
| `note` | 한 줄 설명 | 선택 |

**CityBudget** — 1인 예상 경비 항목

| 열 이름 | 내용 | 필수 여부 |
|---|---|---|
| `city_id` | 대상 도시 | 필수 |
| `item` | 항목 이름 (예: `항공권 (왕복)`) | 필수 |
| `range` | 예상 범위 (예: `28~45만원`) | 필수 |
| `comment` | 항목별 코멘트 | 선택 |

항목별 예상 범위만 보여주고 전체 합계는 따로 계산하지 않습니다(32번
항목 참고) — `item`에 "합계"라고 적은 줄을 넣어도 특별 취급 없이 그냥
평범한 한 줄로 표시됩니다.

**FAQ는 탭이 아니라 도시별 구글독스 문서 하나로 관리합니다.** 새 구글독스
문서를 만들어서, 질문은 "제목1" 스타일로, 그 아래 답변은 일반 문단으로
적습니다(여러 문단도 가능 — 다음 제목이 나오기 전까지 전부 답변으로
묶입니다). 예를 들면:

```
[제목1] 상하이 여행에 비자가 필요한가요?
(본문) 한국 여권 기준 15일 이내 무비자 입국이 가능합니다. ...

[제목1] 여행하기 가장 좋은 시기는 언제인가요?
(본문) 3~5월, 9~11월이 습도와 기온 모두 무난합니다. ...
```

작성이 끝나면 문서 메뉴에서 **파일 > 공유 > 웹에 게시**를 누르고(이번엔
전체 문서를 그대로, csv가 아니라 "웹 페이지" 형식으로) 게시한 뒤 나온
링크를 CityPages 탭의 그 도시 줄 `faq_doc_url` 칸에 붙여넣으면 끝입니다.
질문·답변 모두 시트/독스에 적은 텍스트만 그대로 화면에 옮기고, 문서의
서식(굵게·색상 등)은 반영되지 않습니다 — 안전하게 텍스트만 뽑아오는
방식이라 그렇습니다.

**여행 준비물 2가지(eSIM/유심, 여행자보험)는 시트가 아니라 `city.js`
안에 직접 넣습니다.** 도시마다 달라지는 값이 아니라 사이트 전체가 같이
쓰는 제휴 링크라서 그렇습니다. `CONFIG.prep.esimUrl`, `CONFIG.prep.insuranceUrl`
두 칸에 제휴 링크를 채워 넣으면 됩니다.

**숙소 카드의 예약 버튼은 지역별이 아니라 도시 전체로 하나만 연결됩니다.**
아고다(Agoda)가 "이 지역만", "이 가격대만" 걸러서 보여주는 딥링크를
지원하는지 확인해봤는데, 지원하지 않는 것으로 확인됐습니다. 그래서
가성비/중급/럭셔리처럼 지역이 다른 카드를 만들어도 실제로는 다 같은
"도시 전체" 검색 결과로만 연결할 수 있는데, 카드마다 버튼을 따로 두면
마치 지역별로 다른 곳으로 연결되는 것처럼 오해할 수 있어서, 지금은
지역 카드들 아래에 "OOO 숙소 전체 보기" 버튼 하나만 두는 것으로
정리했습니다. 이 버튼은 14번 항목의 `CONFIG.agoda.cid`와 Cities 탭의
`agoda_slug`(city.js 안에서는 `CONFIG.agoda.cid`)를 그대로 재사용해서
만들어집니다. 나중에 지역/가격대별로 진짜 다른 링크를 만들 수 있는
제휴 프로그램을 찾으시면, 그때 다시 카드별 버튼으로 되돌릴 수 있습니다.

**보안 관련 참고사항.** 시트/독스에 적은 텍스트에 우연히 HTML 태그
비슷한 문자를 넣더라도, 이 페이지는 전부 텍스트로만 취급해서 화면에
그대로 글자로 보여줍니다(즉 시트 내용이 실제 웹페이지 구조를 바꿀 수는
없습니다). 다만 그만큼 시간대별 추천 장소의 `note`처럼 다른 섹션을
가리키는 링크가 필요한 칸에서도 지금은 링크가 아니라 일반 텍스트로만
표시됩니다 — 나중에 필요해지면 안전한 방식으로 다시 검토할 수 있습니다.

**미리보기 방법.** `city.html` 파일을 더블클릭해서 열면(또는 Netlify에
올린 뒤 `city.html?id=CN-SHANGHAI`로 접속하면) 시트/독스를 하나도
연결하지 않은 상태에서도 "상하이" 예시 데이터로 전체 레이아웃을 바로
확인할 수 있습니다.

## 31. 숙소 예약 버튼을 지역별에서 "도시 전체" 하나로 통합

30번 항목에서 처음 만들 때는 숙소 지역 카드(가성비/중급/럭셔리)마다
"이 지역 숙소 둘러보기" 버튼을 하나씩 뒀었는데, 실제로 확인해보니
아고다가 지역이나 가격대로 걸러진 딥링크를 지원하지 않아서 결국 카드
세 개의 버튼이 전부 똑같은 "도시 전체" 링크로 연결되고 있었습니다.
지역별로 다른 곳으로 이어지는 것처럼 보이는데 실제로는 다 같은 곳으로
간다는 게 방문자 입장에서 오해를 살 수 있어서, 카드마다 있던 버튼을
없애고 지역 카드들 아래에 "OOO 숙소 전체 보기" 버튼 하나만 두는 것으로
바꿨습니다.

지역 카드 자체(등급 표시, 지역 이름, 교통 설명, 가격대, 트립콤파니
코멘트)는 그대로 남아있습니다 — 실제로 어디를 예약할지 정하는 데
참고할 "소개" 역할은 여전히 하고, 실제 예약 클릭만 버튼 하나로
모인 것입니다. 이에 맞춰 CityStay 탭의 `link_url` 열은 더 이상 쓰지
않습니다(30번 항목 표에서도 제거했습니다) — 이미 채워두셨어도 무시될
뿐 문제는 없습니다.

## 32. 예산 가이드에서 "합계" 줄 없애기

여행 기간이 3박이든, 5박이든, 일주일이든 사람마다 완전히 달라서
항목들을 그냥 더한 "총 합계" 숫자는 의미가 없다는 판단하에 뺐습니다.
이제 예산 가이드 섹션은 각 항목의 예상 범위만 보여주고, 전체를 더한
줄은 화면에 표시되지 않습니다.

CityBudget 탭 구조 자체는 바뀐 게 없습니다(`city_id`, `item`, `range`,
`comment` 그대로) — 다만 `item`에 "합계"라고 적어둔 줄이 있어도 이제는
자동으로 맨 아래 굵은 글씨로 특별 취급되지 않고, 다른 항목들과 똑같이
평범한 한 줄로 표시됩니다. 이미 시트에 "합계" 줄을 넣어두셨다면 그냥
지우시면 됩니다(안 지워도 페이지가 깨지진 않고, 그냥 평범한 항목 하나로
보일 뿐입니다).

## 33. 로고(파비콘) 새로 그리기 + 검색 결과 제목 문구 변경

## 36. 도시 페이지(city.html)를 나중에 검색에 노출할 준비만 해둠

"트립콤파니 상하이"처럼 검색했을 때 도시 페이지가 나오게 하려면
noindex를 지우는 것 말고도 더 손볼 게 있어서, 그 부분들을 미리 다
만들어뒀습니다. 다만 아직 실제로 공개(색인 허용)하는 건 아니라고
하셔서, city.html은 지금도 여전히 `<meta name="robots"
content="noindex, nofollow">` 상태 그대로이고 검색에는 안 잡힙니다.
아래는 나중에 공개할 때 켜기만 하면 되도록 미리 만들어둔 것들입니다.

**왜 noindex만 지운다고 끝이 아닌가.** city.html은 도시마다 다른
파일이 아니라 `city.html?id=CN-SHANGHAI`, `city.html?id=JP-TOKYO`처럼
파일 하나를 쿼리스트링만 바꿔서 재사용하는 구조입니다. 그런데 지금까지
title/설명만 도시별로 다르게 채워졌고, 검색엔진에게 "이 주소가 진짜
대표 주소"라고 알려주는 `canonical`(대표 URL)이나 `og:url`은 아예
없었습니다. 이 상태로 noindex만 지우면, 구글이 "쿼리스트링만 다른
같은 페이지들"이라고 판단해서 도시 하나만 대표로 남기고 나머지는
전부 중복으로 접어버릴 수 있습니다 — 그러면 도시를 아무리 늘려도
실제로 검색에 잡히는 페이지는 계속 1개뿐인 상태가 됩니다.

**그래서 미리 만들어둔 것.**

- `city.html` — `<head>`에 `canonical`, Open Graph(og:title/description/
  url/image), 트위터(X) 카드, 구조화 데이터(JSON-LD) 자리를 추가했습니다.
  robots는 여전히 `noindex, nofollow`입니다. 실제로 공개할 때 이 값을
  `index, follow`로 바꾸기만 하면 되고, canonical/OG/JSON-LD는 이미
  도시별로 채워지도록 만들어둔 상태라 그때 따로 손댈 건 없습니다.
- `city.js` — 기존에 title/설명만 채우던 코드를 `updatePageSeo()`라는
  함수로 정리하고, 여기서 canonical/og:url을
  `https://tripcompany.world/city.html?id=도시ID` 형태로 도시마다 다르게
  채워 넣도록 추가했습니다. og:title/description, 트위터 제목/설명,
  JSON-LD의 `name`/`url`/`description`도 전부 같은 값으로 같이
  맞춰집니다. `renderHero()`가 도시 데이터를 다 불러온 직후에 이 함수를
  호출하므로, 화면 내용이 바뀌는 시점과 검색엔진용 태그가 바뀌는 시점이
  항상 같습니다. 이건 noindex 여부와 상관없이 항상 작동하는 코드라
  지금 상태로 둬도 문제없습니다.
- `sitemap.xml` — 아직 공개 전이라 상하이 주소는 실제 `<url>` 항목이
  아니라 주석 안에 예시 형식으로만 넣어뒀습니다. 실제로 공개하는
  시점에 그 주석을 실제 `<url>` 블록으로 바꾸고, 다른 도시를 공개할
  때마다 같은 형식으로 하나씩 추가해주시면 됩니다.

**나중에 실제로 공개할 때 할 일은 이 두 가지뿐입니다.** ① city.html의
robots 값을 `index, follow`로 바꾸기, ② sitemap.xml의 해당 도시
`<url>` 블록 주석을 풀기(또는 새로 추가하기). 그 외 canonical/OG/
JSON-LD/title/설명은 이미 도시별로 자동으로 맞춰지도록 만들어져
있어서 추가로 손댈 게 없습니다.

**og:image는 아직 공용 이미지입니다.** 지금은 도시 페이지도 홈과
똑같은 `images/og-image.jpg`를 공유합니다. 나중에 도시별로 다른
공유 이미지를 쓰고 싶으시면, CityPages 탭에 이미지 주소 열을 하나
추가하고 `updatePageSeo()`에서 `og:image`/`twitter:image` 값도
채워주는 코드를 추가하면 됩니다(지금은 그 열이 없어서 공용 이미지로
남겨뒀습니다).

**참고하실 점.** 지도 화면(index.html)에서 이 도시 페이지로 연결되는
링크도 아직 없는 상태입니다 — 나중에 공개할 때는 사이트맵과 주소만
으로도 색인 자체는 가능하지만, 실제로 지도에서 도시를 클릭하면 이
페이지로 연결되는 링크가 있으면 구글이 더 빠르고 안정적으로 찾아갑니다.
그 부분도 필요하시면 그때 같이 작업해드릴게요. 공개 직후에는 16번
항목에서 안내한 대로 구글 서치 콘솔의 "URL 검사 → 색인 생성 요청"을
눌러 재크롤링을 요청하면 반영이 더 빨라집니다.

## 37. 정식 사이트 이름을 "트립콤파니 여행지도"로 확정 (브랜딩)

지금까지 사이트를 가리키는 이름이 "트립콤파니 가이드 지도", 33번
항목에서 잠깐 썼던 "트립콤파니: 모든 세계여행 가이드를 지도로 한 번에
모아보기"처럼 이곳저곳에서 조금씩 다르게 쓰이고 있었는데, 이제
**"트립콤파니 여행지도"** 한 가지로 정식 확정하고 사이트 전체에서
일관되게 쓰이도록 정리했습니다.

**탭 제목 / 공유 카드(og:title, 트위터 카드)** 는 요청하신 형식 그대로
"트립콤파니 여행지도 · 도시를 누르면 그 지역 여행 영상이 전부"로
맞췄습니다. `index.html`의 `<title>`, `og:title`, `twitter:title` 세
곳이 전부 이 문구입니다.

**"트립콤파니 여행지도"라는 이름 자체**는 사이트를 가리키는 자리마다
전부 반영했습니다.

- `index.html` — `og:site_name`(구글 검색 결과 맨 윗줄에 뜨는 값,
  33번 항목 참고), 구조화 데이터(JSON-LD)의 `"name"`, 화면 상단에 보이는
  헤더 문구(`<div class="brand">`, "페이지 제목"에 해당), 지도 영역의
  접근성 라벨(`aria-label`).
- `privacy.html` — `<title>`, 메타 설명, 본문 제1조의 "OOO(이하
  "사이트")는" 문장.
- `app.js` — 모바일에서 공유 버튼을 눌렀을 때(국가/도시를 고르지 않은
  상태라면) 공유창에 뜨는 기본 제목.
- `city.html` / `city.js` — 아직 비공개 상태지만 나중에 공개했을 때
  바로 일관되도록 함께 맞춰뒀습니다. 도시 페이지의 `og:site_name`,
  JSON-LD의 `isPartOf.name`, 그리고 도시별 제목 형식을 `{도시명} 여행
  가이드 · 트립콤파니`에서 `{도시명} 여행 가이드 · 트립콤파니
  여행지도`로 바꿨습니다(예: "상하이 여행 가이드 · 트립콤파니
  여행지도").

**의도적으로 그대로 둔 것.** "트립콤파니"라는 이름이 유튜브 채널 자체를
가리키는 자리(예: 채널 카드의 "트립콤파니", 지도 범례의 "트립콤파니",
구조화 데이터의 `publisher.name`, "트립콤파니가 다녀왔어요"·"순위는
트립콤파니가 직접 정했어요"처럼 트립콤파니 팀이 직접 한 일을 가리키는
본문 문구, "여행하는트콤"과 짝을 이루는 채널 구분 값)는 바꾸지
않았습니다. 이건 사이트 이름이 아니라 실제 유튜브 채널·팀을 가리키는
말이라, "트립콤파니 여행지도"로 바꾸면 오히려 어색하고 뜻도
달라지기 때문입니다. 즉 "사이트 이름 = 트립콤파니 여행지도",
"채널/팀 이름 = 트립콤파니"로 구분해서 정리했다고 이해하시면 됩니다.

## 38. 임베드 영상 광고 수익 살리기 + 오른쪽 영상 목록에 채널별 필터 탭 추가

**1) 영상 재생 모달에서 `autoplay=1` 제거 (광고/수익 문제).** 영상
카드를 클릭했을 때 뜨는 재생 모달이 지금까지는 유튜브 임베드를
`autoplay=1`로 열어서 클릭하자마자 바로 재생되게 해뒀는데, 이 방식이
유튜브 광고가 아예 안 붙는 원인이었습니다. 유튜브 공식 정책상 임베드
영상에 광고가 붙으려면 "스크립트로 강제 재생"이 아니라 "방문자가 그
안에서 직접 한 번 더 눌러서 재생하는(click-to-play)" 방식이어야
합니다(공식 도움말: support.google.com/youtube/answer/132596).

- `app.js`의 `openVideoModal()`: iframe 주소에서 `autoplay=1`을
  빼서 `https://www.youtube-nocookie.com/embed/{영상ID}?rel=0`
  형태로 바꿨습니다. 이제 모달을 열면 유튜브 썸네일과 재생 버튼만
  먼저 뜨고, 방문자가 그 버튼을 한 번 더 눌러야 실제 재생이
  시작됩니다 — 클릭 한 번이 더 필요해진 대신, 그래야 광고가 정상
  적으로 붙어서 채널 수익(트립콤파니/여행하는트콤 두 채널 모두, 각
  영상의 실제 소유 채널로 수익이 들어갑니다)으로 이어집니다.
- 이 변경은 재생 화면에만 영향을 주고, 영상 카드 목록이나 GA4
  `video_open` 이벤트 등 다른 동작에는 영향이 없습니다.

**2) 오른쪽 영상 목록 위에 채널별 필터 탭 추가.** 나라/도시를
선택했을 때 오른쪽에 뜨는 영상 목록 맨 위에 "전체보기" · "트립콤파니"
· "여행하는트콤" 세 개의 탭을 추가해서, 방문자가 원하는 채널 영상만
골라 볼 수 있게 했습니다.

- `index.html`: `.panel-heading-row`(제목+공유 버튼)와
  `#video-list` 사이에 `#channel-tabs` 탭 바를 추가했습니다. 나라를
  아직 고르지 않은 초기 화면에서는 `hidden` 속성으로 숨겨져 있습니다.
- `app.js`:
  - `activeChannelFilter`(전역 변수, 기본값 `"all"`)로 지금 선택된
    탭을 기억합니다.
  - `getFilteredVideos()`가 이 값을 반영해서 목록을 걸러줍니다 —
    영상 목록뿐 아니라, 재생 모달 하단의 "이어서 볼 영상" 추천 목록도
    같은 함수를 재사용하기 때문에 자동으로 필터가 함께 적용됩니다
    (예: "트립콤파니" 탭에서 보다가 영상을 재생해도, 추천 목록에는
    여행하는트콤 영상이 섞이지 않습니다).
  - `renderChannelTabs()`가 나라/도시 선택 여부에 따라 탭 바를
    보이거나 숨기고, 지금 선택된 탭에 하이라이트(`.is-active`)를
    표시합니다. `renderVideoPanel()`이 다시 그려질 때마다 함께
    호출됩니다.
  - `bindChannelTabEvents()`가 탭 클릭을 처리합니다(다른 목록들과
    같은 위임 방식). 탭을 누르면 `activeChannelFilter`를 바꾸고
    `renderVideoPanel()`을 다시 호출해서 목록을 새로 그립니다.
  - 필터 때문에 목록이 0개가 되면("트립콤파니" 탭인데 이 지역엔
    트립콤파니 영상이 없는 경우) "○○ 영상은 아직 없습니다. 다른
    탭도 확인해보세요."라고 안내해서, 그 지역에 영상이 아예 없다는
    오해를 하지 않도록 했습니다.
  - **필터 초기화 시점** — 나라를 새로 고르거나(`selectCountry`)
    "내 위치" 버튼으로 세계지도로 돌아가면(`handleBackButtonClick`)
    필터가 "전체보기"로 자동 초기화됩니다. 같은 나라 안에서 다른
    도시로 옮겨갈 때는(`selectCity`) 방문자가 고른 필터를 그대로
    유지합니다 — 예를 들어 "트립콤파니" 탭을 보다가 같은 나라의 다른
    도시를 눌러도 계속 트립콤파니 영상만 보입니다.
- `style.css`: `.channel-tabs`/`.channel-tab` 스타일을 추가했습니다.
  선택된 탭의 색은 기존 채널 배지 색과 통일했습니다 — "트립콤파니"는
  주황(`#e8871e`), "여행하는트콤"은 파랑(`#3b6fd6`), "전체보기"는
  사이트 기본 강조색(`--accent`).

## 39. 채널 필터 탭 클릭을 GA4 이벤트(`channel_filter`)로 기록

38번에서 추가한 오른쪽 영상 목록 위의 채널 필터 탭("전체보기" ·
"트립콤파니" · "여행하는트콤")은 지금까지 화면만 바뀌고 통계에는 아무
것도 남지 않았습니다. 방문자들이 이 탭을 실제로 쓰는지, 어느 채널
영상을 골라 보는지 확인할 수 있도록 GA4 맞춤 이벤트를 붙였습니다.

**보내는 이벤트 이름:** `channel_filter`

**함께 보내는 값(이벤트 파라미터):**

| 파라미터 | 뜻 | 예시 |
| --- | --- | --- |
| `filter_channel` | 방문자가 고른 탭 | `all` / `trip` / `trekom` |
| `filter_label` | 그 탭의 화면 표기(보고서에서 바로 읽히는 값) | `전체보기` / `트립콤파니` / `여행하는트콤` |
| `previous_filter` | 누르기 직전에 보고 있던 탭 | `all` |
| `region_type` | 그때 보고 있던 단위 | `country` / `city` |
| `region_name` | 영상 패널 제목에 표시된 지역 이름 | `일본 · 도쿄` |
| `region_slug` | 공유 링크(`?region=`)에 쓰는 지역 코드 | `tokyo` |
| `result_count` | 탭을 누른 결과 실제로 남은 영상 개수 | `2` |

`result_count`가 있으면 "탭은 눌렀는데 볼 게 없었던" 조합(예: 그
지역엔 여행하는트콤 영상이 하나도 없어서 0개)을 GA4에서 바로 찾아낼
수 있습니다. 그런 지역·채널 조합이 반복해서 잡히면 영상을 더
채우거나 탭을 숨기는 판단 근거로 쓸 수 있습니다.

**"방문자가 직접 누른 경우"만 보냅니다.** 나라를 새로 고르거나(
`selectCountry`) "내 위치" 버튼으로 세계지도로 돌아가면(
`handleBackButtonClick`) 필터가 "전체보기"로 자동 초기화되는데,
이건 방문자의 선택이 아니라 화면 초기화라서 이벤트를 보내지
않습니다. 안 그러면 지도를 클릭한 횟수만큼 "전체보기"가 부풀려져서
통계가 쓸모없어집니다. 같은 탭을 다시 눌렀을 때도(변화 없음) 보내지
않습니다.

**바뀐 파일:**

- `app.js`
  - `bindChannelTabEvents()`: 탭을 눌러 필터가 실제로 바뀐 경우에만,
    목록을 다시 그린 **뒤에** `trackChannelFilter()`를 호출합니다.
    순서가 중요합니다 — 다시 그리기 전에 보내면 `result_count`가
    방문자가 실제로 보게 된 화면과 달라집니다.
  - `trackChannelFilter(filter, previousFilter)` 함수 추가 — 위 표의
    값들을 모아서 기존 `trackEvent()`로 보냅니다. `region_name`은
    `video_open` 이벤트와 같은 방식으로 `#panel-heading`의 텍스트를
    그대로 씁니다.
  - `channelFilterLabel(filter)` 함수 추가 — `all`은 "전체보기",
    나머지는 기존 `CHANNEL_LABEL`(트립콤파니/여행하는트콤)을 씁니다.
  - `trackEvent()` 위 주석의 "이 사이트가 GA4로 보내는 맞춤 이벤트"
    목록을 실제와 맞게 일곱 가지로 갱신했습니다(`channel_filter`와
    그동안 빠져 있던 `city_search`, `city_search_no_result` 추가).

`index.html`, `style.css`는 이번에 건드리지 않았습니다. 기존 탭
동작(필터링, 활성 탭 표시, 초기화 시점)도 그대로입니다.

**GA4에서 실제로 보려면 (관리자 화면 설정, 코드와 별개):** 34~35번
항목에서 안내한 것과 같습니다 — GA4 관리 > 맞춤 정의 >
"맞춤 측정기준 만들기"에서 `filter_label`, `filter_channel`,
`region_name`, `region_slug` 같은 파라미터를 이벤트 범위로 등록해야
보고서에서 쪼개 볼 수 있고, `result_count`는 숫자라서 "맞춤 측정항목"
쪽에 등록합니다. **등록 이전에 쌓인 데이터에는 소급 적용되지
않으므로**, 배포하면서 같이 등록해두는 편이 좋습니다. 등록 없이도
실시간 보고서와 DebugView에서는 이벤트가 들어오는 것을 바로 확인할 수
있습니다.

**검증:** Playwright로 실제 브라우저를 띄워 21가지를 확인했습니다 —
탭을 누르면 이벤트가 정확히 1번만 나가는지, 파라미터 값(특히
`previous_filter`와 `result_count`)이 맞는지, 같은 탭을 다시 누르면
안 나가는지, 나라 선택/세계지도 복귀 같은 자동 초기화에서는 안
나가는지, 영상이 0개가 되는 조합에서 `result_count`가 0으로 잡히는지
등입니다. `node --check app.js` 문법 검사도 통과했습니다.

## 40. 사이트 점검 후 발견한 문제 6가지 수정 (깨진 영상 카드 · h1 · 안전한 광고 링크 · 로딩 속도 · 접근성)

배포된 사이트를 실제 브라우저로 열어 라이브 데이터(영상 231줄 · 도시
85줄)로 점검하다가 찾은 문제들을 한 번에 고쳤습니다.

### 1) 제목 없는 "깨진 영상 카드"가 실제로 노출되던 문제 (가장 중요)

구글시트 Videos 탭에 `video_id`만 적어두고 `youtube_url`·`title`은
아직 비어 있는 줄이 3개 있었습니다(`v20` 하노이, `v36` 미국 개요,
`v54` 그랜드캐니언). 앱이 이 줄도 그대로 카드로 그리는 바람에, 하노이
같은 지역을 열면 **회색 깨진 썸네일 + 제목 없음 + 채널 배지만 있는
카드**가 영상 목록에 섞여 있었습니다. 링크는
`youtube.com/watch?v=`(영상 ID가 빈 주소)라서 눌러도 아무 영상이 안
나왔습니다.

`app.js`에 `sanitizeData()`를 새로 만들어서, **데이터를 받아온 직후 한
곳에서** 아래 줄들을 걸러냅니다.

- 영상: 유튜브 주소에서 영상 ID를 뽑아낼 수 없는 줄
- 도시: `city_id`나 도시 이름이 비어 있는 줄(실제로 완전히 빈 줄이 1개
  있었습니다)
- 나라: `country_code`가 비어 있는 줄

한 곳에서 거르기 때문에 영상 목록, 재생 모달의 "이어서 볼 영상", 도시
마커, 검색, 헤더 통계까지 **전부 자동으로** 깨끗해집니다. 최신 데이터
경로(`init()`)와 지난 방문 때 저장해둔 캐시(`readDataCache()`) 양쪽에
모두 적용했고, 걸러낸 결과가 캐시에 저장되므로 예전 버전이 저장해둔
캐시도 다음 방문에 정리됩니다.

**시트는 건드리지 않았습니다**(이 프로젝트 규칙). 나중에 그 줄에 유튜브
주소를 채워 넣으면 코드를 고칠 필요 없이 그대로 다시 화면에 나옵니다.
다만 그 3줄은 어차피 쓸 일이 없다면 시트에서 지우셔도 됩니다.

### 2) 헤더의 "OO개의 가이드" 숫자가 부풀려지던 문제

1번과 같은 원인이었습니다. 빈 줄 3개까지 세는 바람에 실제 유효 영상은
166개인데 화면에는 **169개**로 표시되고 있었습니다. 이제 걸러낸 뒤에
세므로 자동으로 맞습니다(`renderSiteStats()` 코드는 그대로입니다).

### 3) 페이지에 `<h1>`이 아예 없던 문제 (SEO)

헤더의 사이트 이름이 `<div class="brand">`라서, 검색엔진이 "이 페이지의
대표 제목"으로 삼을 `<h1>`이 페이지에 하나도 없었습니다. 태그만
`<h1 class="brand">`로 바꾸고, `style.css`의 `.brand`에 `margin: 0`을
더해서 **화면에 보이는 모양은 이전과 완전히 동일**하게 유지했습니다.

### 4) 시트에서 온 주소가 그대로 링크에 들어가던 문제 (프로젝트 규칙 위반)

지역 맞춤 광고 카드(`buildLocalAdCardHtml()`)가 LocalAds 탭의
`local_ad_url`·`local_ad_image`를 `escapeHtml()` 없이 `href`/`src`에
그대로 넣고 있었습니다. 시트 값에 따옴표가 들어가면 마크업이 깨지고,
`javascript:`로 시작하는 주소가 들어가면 그대로 실행됩니다.

- `safeUrl()` 함수를 새로 만들었습니다 — `http://`, `https://`,
  사이트 내부 경로(`/images/...`)만 통과시키고 나머지는 빈 문자열로
  만듭니다.
- 광고 주소가 통과하지 못하면 그 광고 카드를 **아예 만들지 않습니다**
  (깨진 링크를 보여주는 것보다 안 보여주는 편이 낫습니다).
- 통과한 주소도 `escapeHtml()`을 거쳐 넣습니다.
- 아고다·클룩·트립닷컴 배너의 `href`에도 같은 이스케이프를
  적용했습니다(주소는 우리가 만들지만 시트의 slug 값이 섞여 들어가기
  때문입니다).

### 5) 첫 화면 로딩 속도 — `preconnect` 힌트 추가

첫 화면을 그리려면 반드시 필요한 바깥 서버 3곳에 미리 연결해두는
`<link rel="preconnect">`를 `index.html` `<head>`에 넣었습니다.

- `cdn.jsdelivr.net` — 지도 라이브러리(Leaflet)와 세계 국경 데이터
- `docs.google.com` — 구글시트 CSV(나라/도시/영상)
- `img.youtube.com` — 영상 카드 썸네일

DNS 조회·연결·암호화 협상이 실제 다운로드 전에 미리 끝나 있어서, 특히
모바일 네트워크에서 지도와 영상 목록이 뜨는 시점이 앞당겨집니다.

### 6) 채널 필터 탭 접근성 마무리 (39번의 후속)

38번에서 만든 탭에 `role="tab"`은 있었지만 연결된 패널이 없었고,
키보드로는 Tab 키를 세 번 눌러야 세 탭을 오갈 수 있었습니다.

- `index.html`: 각 탭에 `aria-controls="video-list"`를 달고,
  `#video-list`에 `role="tabpanel"`과 설명 라벨을 줬습니다.
- `app.js` `renderChannelTabs()`: 선택된 탭만 `tabindex="0"`,
  나머지는 `-1`(roving tabindex) — 표준 탭 동작대로 Tab 키로는 탭
  묶음에 한 번만 들어오게 됩니다.
- `app.js` `bindChannelTabEvents()`: `←`/`→`(`↑`/`↓`)로 옆 탭,
  `Home`/`End`로 처음·마지막 탭으로 이동하고 바로 선택됩니다.
- 클릭과 키보드가 모두 새 `activateChannelTab()` 한 곳을 거치므로,
  39번에서 추가한 `channel_filter` GA4 이벤트도 키보드 선택에서 똑같이
  한 번만 나갑니다.

### 검증

Playwright로 실제 브라우저를 띄워 **24가지**를 확인했습니다 — 빈 줄이
실제로 걸러지는지, 하노이 화면에 깨진 카드가 사라졌는지, 통계 숫자가
맞는지, `javascript:` 주소가 페이지 어디에도 안 들어가는지, 정상 광고는
그대로 나오는지, `h1`이 하나이고 여백이 0인지, preconnect 3줄이 있는지,
화살표·Home·End 키가 동작하고 초점과 `tabindex`가 함께 옮겨지는지
등입니다. 39번에서 만든 기존 테스트 21가지도 다시 돌려 회귀가 없음을
확인했고, `node --check app.js`도 통과했습니다.
